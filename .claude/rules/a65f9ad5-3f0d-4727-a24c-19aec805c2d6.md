<rule_activation id="a65f9ad5-3f0d-4727-a24c-19aec805c2d6" title="Adopt Explicit Export Pattern for Library Module Public APIs: React Components Exposed" applies_to="packages/core/lib/**/*,packages/core/components/**/*">
These rules are ALWAYS ACTIVE for all public-facing modules under packages/core/lib/ and packages/core/components/.
</rule_activation>

### Rules

- **R-EXP-001** SHOULD: React components exposed as library modules SHOULD follow a consistent index.tsx export pattern for discoverability.
- **R-EXP-002** SHOULD: Use TypeScript's 'export type' for type-only exports to prevent runtime inclusion in bundles.
- **R-EXP-003** SHOULD: Establish naming conventions: index.tsx for component exports, descriptive names for utilities (e.g., flatten-data.ts, populate-ids.ts).
- **R-EXP-004** SHOULD: For server-specific modules, use .server.tsx extension and configure bundler to exclude from client builds.
- **R-EXP-005** MUST: All public-facing modules under packages/core/lib and packages/core/components MUST have explicit export statements.
- **R-EXP-006** MUST: No internal helper functions or private utilities MUST be exported from public API modules.
- **R-EXP-007** MUST: Server-specific modules MUST use .server.tsx extension and MUST NOT be imported in client-side code.
- **R-EXP-008** MUST: Package.json exports field MUST restrict access to only intended public modules.

### Verify

```bash
# Count explicit export statements in public modules
grep -r 'export {' packages/core/lib packages/core/components | wc -l

# Find all index files (component entry points)
find packages/core -name 'index.tsx' -o -name 'index.ts' | wc -l

# Run API Extractor to detect breaking changes and unintended exports
npx api-extractor run --local || echo 'API surface check'

# Verify server-specific modules use correct naming convention
grep -r '\.server\.' packages/core/components | grep -v node_modules
```

**Accept when:**
- All public-facing modules under packages/core/lib and packages/core/components have explicit export statements
- No internal helper functions or private utilities are exported from public API modules
- Server-specific modules use .server.tsx extension and are not imported in client-side code
- Package.json exports field restricts access to only intended public modules
- API Extractor runs successfully without detecting unintended breaking changes
- New public APIs include TSDoc comments and are documented in centralized API reference
