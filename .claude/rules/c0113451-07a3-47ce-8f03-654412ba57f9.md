<rule_activation id="c0113451-07a3-47ce-8f03-654412ba57f9" title="Implement Server-Side Request Logging in Remix Entry Points: Applications Implement Structured" applies_to="**/entry.server.tsx">
These rules are ALWAYS ACTIVE for all Remix applications with server-side rendering capabilities. They govern logging implementation in entry.server.tsx files to ensure comprehensive observability at the server entry point.
</rule_activation>

### Rules

- **R-REMIX-LOG-001** MAY: Applications MAY implement structured logging formats (JSON) for easier parsing and analysis in log aggregation systems.

### Verify

```bash
# Check for entry.server.tsx file and logging implementation
grep -r 'entry.server.tsx' app/ && grep -E '(console\.log|logger\.|log\()' app/entry.server.tsx

# Verify entry.server.tsx exists and contains request handling
test -f app/entry.server.tsx && grep -E '(handleRequest|handleDataRequest)' app/entry.server.tsx

# Check for logging tests
npm test -- --grep 'entry.server.*logging' || echo 'Add tests for entry.server logging'
```

**Accept when:**
- The entry.server.tsx file contains logging implementation that captures request method, URL, and status code
- Verification commands successfully identify logging statements in entry.server.tsx
- Manual code review confirms that sensitive data is filtered from logs and performance impact is minimal
- Structured logging format (JSON) is implemented for production environments
- Correlation IDs or request tracing identifiers are included in log output

<enforcement>
Claude Code MUST verify logging implementation in entry.server.tsx files before approving Remix applications. Verification is mandatory and non-deferrable. CI/CD pipeline warnings for missing logging must be addressed before production deployment.
</enforcement>
