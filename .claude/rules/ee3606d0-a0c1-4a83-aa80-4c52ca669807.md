<rule_activation id="ee3606d0-a0c1-4a83-aa80-4c52ca669807" title="Standardize Jest Testing Framework with React Testing Library for Component Tests: Tests Use Snapshot" applies_to="**/*">
These rules are ALWAYS ACTIVE for all test file creation and maintenance within the CI/CD pipeline, covering all TypeScript and TSX files in packages/core and related packages.
</rule_activation>

### Rules

- **R-JEST-001** MAY: Tests MAY use snapshot testing for stable UI components, but should not rely solely on snapshots.

### Verify

```bash
# Verify Jest test files exist with correct naming convention
grep -r "describe\|it\|test" packages/*/lib/**/__tests__/*.spec.tsx | head -5

# Find all test files with .spec.tsx or .spec.ts extensions
find packages -type f -name '*.spec.tsx' -o -name '*.spec.ts' | head -10

# Verify React Testing Library is a dependency
grep -r "@testing-library/react" packages/*/package.json

# List all test files executable by Jest
npm test -- --listTests | grep __tests__
```

**Accept when:**
- All test files use `.spec.tsx` or `.spec.ts` extensions and are located in `__tests__` directories
- Jest configuration is present in `package.json` or `jest.config.js` files
- React Testing Library is listed as a dependency in packages containing React component tests
- Tests execute successfully in CI/CD pipeline without manual intervention
- Snapshot tests are used only for stable UI components and not as the sole testing strategy

<enforcement>
Claude Code MUST verify all test files comply with Jest and React Testing Library standards. Verification is mandatory on every pull request. Pull requests without tests or with failing tests MUST be blocked from merging. Coverage drops below threshold MUST trigger CI/CD failure.
</enforcement>
