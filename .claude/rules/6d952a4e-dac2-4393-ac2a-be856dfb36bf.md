### Rules

- **R-JEST-001** MUST: Test files MUST be organized in `__tests__` directories co-located with the source code they test.
- **R-JEST-002** MUST: All test files MUST use `.spec.tsx` or `.spec.ts` extensions.
- **R-JEST-003** MUST: Jest MUST be configured as the test runner and all tests MUST execute successfully with `npm test`.
- **R-JEST-004** MUST: React component tests MUST import and use `@testing-library/react` for rendering and queries.
- **R-JEST-005** MUST: Test coverage reports MUST be generated successfully and meet minimum threshold requirements.
- **R-JEST-006** SHOULD: Configure Jest with TypeScript support using ts-jest or @swc/jest for faster compilation.
- **R-JEST-007** SHOULD: Create shared test helpers and fixtures in `__helpers__` directories to promote reusability and reduce duplication.
- **R-JEST-008** SHOULD: Use snapshots sparingly and only for stable serialized output; prefer explicit assertions for critical behavior.
- **R-JEST-009** SHOULD: Balance unit tests with integration tests that use minimal mocking; establish guidelines for when mocking is appropriate.

### Verify

```bash
# Count test files using describe/it/test patterns
grep -r "describe\|it\|test" packages/core/**/__tests__/**/*.spec.tsx | wc -l

# Count __tests__ directories
find packages/core -type d -name '__tests__' | wc -l

# Verify React Testing Library usage
grep -r "@testing-library/react" packages/core/**/__tests__/**/*.spec.tsx | wc -l

# List all test files with correct extensions
npm test -- --listTests | grep -E '\.spec\.(tsx|ts)$' | wc -l
```

**Accept when:**
- All test files use `.spec.tsx` or `.spec.ts` extensions and are located in `__tests__` directories
- Jest is configured as the test runner and all tests execute successfully with `npm test`
- React component tests import and use `@testing-library/react` for rendering and queries
- Test coverage reports are generated successfully and meet minimum threshold requirements
- CI pipeline runs Jest test suite on every pull request and blocks merge on test failures
- ESLint rules enforce testing-library best practices via eslint-plugin-testing-library
- Code review checklist includes verification of test file naming and location conventions
- Pre-commit hooks run tests for changed files to catch failures early
