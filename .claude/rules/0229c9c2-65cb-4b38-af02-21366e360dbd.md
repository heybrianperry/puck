<rule_activation id="0229c9c2-65cb-4b38-af02-21366e360dbd" title="Implement Message Queue Logging for State Management Operations: Queue Depth Backlog" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching state management operations that cross component boundaries via message queues, particularly in use-puck.ts and Puck/index.tsx.
</rule_activation>

### Rules

- **R-MQL-001** SHOULD: Queue depth and backlog metrics SHOULD be logged periodically for operational monitoring.
- **R-MQL-002** MUST: All message queue enqueue and dequeue operations in use-puck.ts and Puck/index.tsx include structured log statements.
- **R-MQL-003** MUST: Correlation IDs MUST be present in logs and traceable through message lifecycle from enqueue to completion.
- **R-MQL-004** MUST: Implement structured logging with JSON format to enable efficient querying and analysis in log aggregation systems.
- **R-MQL-005** MUST: Use asynchronous logging with buffering to mitigate performance degradation in high-throughput message processing.
- **R-MQL-006** MUST: Implement mandatory payload sanitization to prevent accidental logging of sensitive user data or credentials.
- **R-MQL-007** SHOULD: Configure log levels appropriately: INFO for enqueue/dequeue, WARN for retries, ERROR for failures, DEBUG for detailed payloads.
- **R-MQL-008** MAY: Implement sampling-based logging (log 1 in N messages) for high-frequency operations when log volume exceeds storage capacity.

- All message queue enqueue and dequeue operations in use-puck.ts and Puck/index.tsx include structured log statements
- Correlation IDs are present in logs and can be traced through message lifecycle from enqueue to completion
- Unit tests verify that logging occurs for success and failure scenarios in message processing
- Structured logging uses JSON format for efficient querying
- Payload sanitization is implemented and verified through security review
- Asynchronous logging with buffering is configured to prevent performance degradation
