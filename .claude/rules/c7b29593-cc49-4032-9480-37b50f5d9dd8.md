<rule_activation id="c7b29593-cc49-4032-9480-37b50f5d9dd8" title="Implement Server-Side Request Logging in Remix Entry Points: Error Conditions During" applies_to="**/entry.server.tsx">
These rules are ALWAYS ACTIVE for all Remix applications with server-side rendering capabilities, specifically governing logging implementation in entry.server.tsx files.
</rule_activation>

### Rules

- **R-SSR-001** SHOULD: Error conditions during server-side rendering SHOULD be logged with full stack traces and request context.

### Verify

```bash
# Check for entry.server.tsx file and logging statements
grep -r 'entry.server.tsx' app/ && grep -E '(console\.log|logger\.|log\()' app/entry.server.tsx

# Verify entry.server.tsx exists and contains request handling
test -f app/entry.server.tsx && grep -E '(handleRequest|handleDataRequest)' app/entry.server.tsx

# Check for logging tests
npm test -- --grep 'entry.server.*logging' || echo 'Add tests for entry.server logging'
```

**Accept when:**
- The entry.server.tsx file contains logging implementation that captures request method, URL, and status code
- Verification commands successfully identify logging statements in entry.server.tsx
- Manual code review confirms that sensitive data is filtered from logs and performance impact is minimal
- Error conditions are logged with full stack traces and request context
- Logging is environment-aware (verbose in dev, structured JSON in production)

<enforcement>
Claude Code MUST verify logging implementation in entry.server.tsx files before accepting Remix applications. Verification is mandatory and non-deferrable.
</enforcement>
