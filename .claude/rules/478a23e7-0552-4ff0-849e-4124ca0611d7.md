<rule_activation id="478a23e7-0552-4ff0-849e-4124ca0611d7" title="Standardize Logging and Observability Configuration in Runtime Environments: Runtime Components Implement" applies_to="**/*">
These rules are ALWAYS ACTIVE for all TypeScript/JavaScript runtime components (libraries, servers, CLI tools) across the codebase.
</rule_activation>

### Rules

- **R-LOG-001** MUST: All runtime components MUST implement standardized logging configuration that adapts to the execution environment (development, production, test).
- **R-LOG-002** MUST: All components in packages/ and recipes/ directories MUST use environment-based logging configuration rather than hardcoded console statements.
- **R-LOG-003** MUST: Environment variables like LOG_LEVEL, LOG_FORMAT, and NODE_ENV MUST control logging behavior across all components.
- **R-LOG-004** MUST: For server-side components, logging configuration MUST be initialized in the earliest possible module (before application bootstrap) to capture all startup events.
- **R-LOG-005** MUST: Direct console usage in production code paths MUST NOT be permitted without approved exceptions.
- **R-LOG-006** SHOULD: Scaffolding templates in create-puck-app and similar tools SHOULD include proper logging configuration by default.
- **R-LOG-007** SHOULD: A shared configuration module (e.g., @puck/logging-config) SHOULD encapsulate environment detection and logger initialization logic.
- **R-LOG-008** SHOULD: Standard log levels (error, warn, info, debug, trace) SHOULD be documented with guidelines for when each level should be used.

### Verify

```bash
# Count direct console usage in TypeScript/JavaScript files
grep -r 'console\.(log|error|warn)' --include='*.ts' --include='*.js' packages/ recipes/ | wc -l

# Verify environment variable usage for logging configuration
grep -r 'process\.env\.LOG_LEVEL\|process\.env\.NODE_ENV' --include='*.ts' --include='*.js' packages/ recipes/ | wc -l

# Check ESLint enforcement of no-console rule
npm run lint -- --rule 'no-console: error' 2>&1 | grep -c 'no-console'
```

**Accept when:**
- All components in packages/ and recipes/ directories use environment-based logging configuration rather than hardcoded console statements
- Grep for environment variable usage (LOG_LEVEL, NODE_ENV) returns matches in at least 80% of runtime components
- Linting rules enforce structured logging patterns and flag direct console usage in production code paths
- CI pipeline verification passes without console usage violations in production code

<enforcement>
Claude Code MUST verify logging configuration compliance before approving changes to runtime components. Verification is mandatory and MUST NOT be skipped or deferred. Code review MUST block merge requests that introduce non-compliant logging patterns.
</enforcement>
