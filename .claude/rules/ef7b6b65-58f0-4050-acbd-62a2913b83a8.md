These rules are ALWAYS ACTIVE for all React component tests and TypeScript utility function tests in the packages/core directory.
</rule_activation>

### Rules

- **R-JEST-001** SHOULD: Component tests SHOULD follow user-centric testing patterns by querying elements via accessible roles and labels rather than implementation details.

### Verify

```bash
# Count test files using describe/it/test patterns
grep -r "describe\|it\|test" packages/core/**/__tests__/**/*.spec.tsx | wc -l

# Count __tests__ directories
find packages/core -type d -name '__tests__' | wc -l

# Verify React Testing Library usage
grep -r "@testing-library/react" packages/core/**/__tests__/**/*.spec.tsx | wc -l

# List all test files with correct extensions
npm test -- --listTests | grep -E '\.spec\.(tsx|ts)$' | wc -l
```

**Accept when:**
- All test files use .spec.tsx or .spec.ts extensions and are located in __tests__ directories
- Jest is configured as the test runner and all tests execute successfully with 'npm test'
- React component tests import and use @testing-library/react for rendering and queries
- Test coverage reports are generated successfully and meet minimum threshold requirements
- Tests query elements via accessible roles and labels (getByRole, getByLabelText) rather than implementation details (getByTestId, querySelector)

<enforcement>
Claude Code MUST NOT skip or defer verification. All test files must conform to the Jest and React Testing Library standards before acceptance.
</enforcement>
