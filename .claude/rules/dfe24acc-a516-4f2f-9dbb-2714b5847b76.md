<rule_activation id="dfe24acc-a516-4f2f-9dbb-2714b5847b76" title="Adopt Browser-Based Rendering Model for E2E Testing Infrastructure: E2e Test Utilities" applies_to="scripts/e2e/**/*">
These rules are ALWAYS ACTIVE for all E2E test utility files and test infrastructure matching `scripts/e2e/**/*`.
</rule_activation>

### Rules

- **R-E2E-001** SHOULD: E2E test utilities SHOULD expose public contracts for common rendering operations to promote reusability across test suites.
- **R-E2E-002** MUST: E2E test utilities that interact with browser rendering engines MUST use browser-native rendering APIs (getBoundingClientRect, getComputedStyle, etc.).
- **R-E2E-003** MUST: Test setup modules MUST initialize browser contexts with consistent configurations before running tests.
- **R-E2E-004** SHOULD: Helper functions that measure or validate UI element properties SHOULD implement explicit wait mechanisms and layout stabilization checks before measuring element properties.
- **R-E2E-005** SHOULD: E2E test utilities SHOULD be centralized in scripts/e2e/utils/ directory for shared rendering operations.
- **R-E2E-006** MUST: E2E tests MUST NOT use virtual DOM implementations (JSDOM) for visual validation or bounding box measurements.
- **R-E2E-007** SHOULD: Public API contracts for utility functions SHOULD be documented to ensure consistent usage across test suites.

### Verify

```bash
# Check for browser-native rendering APIs in E2E utilities
grep -r 'getBoundingClientRect\|getComputedStyle' scripts/e2e/utils/ --include='*.mjs' --include='*.js'

# Verify required utility modules exist
test -f scripts/e2e/utils/setup.mjs && test -f scripts/e2e/utils/get-box.mjs

# Run E2E test suite and verify tests pass
npm test -- --grep 'e2e' 2>&1 | grep -q 'passed' || echo 'E2E tests not found or failing'
```

**Accept when:**
- E2E utility modules exist in scripts/e2e/utils/ and use browser-native rendering APIs (getBoundingClientRect, getComputedStyle, etc.)
- Test setup modules initialize browser contexts with consistent configurations before running tests
- E2E test suite passes successfully with rendering-based validations for UI element properties
- Centralized utility modules (setup.mjs, get-box.mjs) are present in scripts/e2e/utils/ directory
- Helper functions implement explicit wait mechanisms and layout stabilization checks before measuring element properties
