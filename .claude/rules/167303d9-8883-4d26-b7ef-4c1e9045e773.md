These rules are ALWAYS ACTIVE for all files matching public-facing REST APIs, external webhook receivers, GraphQL mutations, and API gateway integration points that trigger state changes.
</rule_activation>

### Rules

- **R-MQ-001** SHOULD: Message queue publishers SHOULD implement retry logic with exponential backoff for transient failures

### Verify

```bash
# Detect message queue publisher patterns in API layer
grep -r "publish.*Event\|sendMessage\|enqueue" packages/*/src/api --include="*.ts" | grep -v test

# Verify message queue abstraction imports
grep -r "import.*MessageQueue\|import.*EventBus" packages/core packages/tsup-config --include="*.ts"

# Count direct service invocations in API layer (should be minimal/documented)
find . -name "*.ts" -path "*/api/*" -exec grep -l "await.*service\." {} \; | wc -l
```

**Accept when:**
- All public API endpoints that trigger state changes publish events to message queues rather than making direct service calls
- Message queue integration code is located in API boundary layers (controllers, resolvers) and not in core domain services
- Event schemas are documented with version numbers and backward compatibility is maintained across versions
- Retry logic with exponential backoff is implemented for transient failures
- Message queue abstraction layer is used to avoid vendor lock-in
- Idempotency keys are present in event payloads
- Dead letter queues are configured for failed message handling
