<rule_activation id="e009f796-3db4-4718-afe0-2e49b47261ec" title="Adopt Co-located __tests__ Directories for Core Library Unit Tests" applies_to="packages/core/**">
These rules are ALWAYS ACTIVE for all unit tests within the packages/core library. Test files MUST be co-located with source code in __tests__ directories following Jest conventions.
</rule_activation>

### Rules

- **R-COLOCATED-001** MUST NOT: Test files MUST NOT be placed in separate top-level test directories disconnected from the source code they test.
- **R-COLOCATED-002** MUST: All unit tests within packages/core library MUST use co-located __tests__ directories adjacent to source code.
- **R-COLOCATED-003** MUST: TypeScript React test files MUST use the .spec.tsx naming convention for explicit test file identification.
- **R-COLOCATED-004** MUST: Build configuration MUST explicitly exclude __tests__ directories and .spec.tsx files from production bundles.
- **R-COLOCATED-005** MUST: Jest or test runner configuration MUST include __tests__ in test discovery patterns.
- **R-COLOCATED-006** SHOULD: Shared test helpers SHOULD be organized in __helpers__ subdirectories within __tests__ and exported via index files.
- **R-COLOCATED-007** SHOULD: When moving or renaming source files, corresponding test files SHOULD be moved to maintain co-location.
- **R-COLOCATED-008** MAY: Legacy test files that exist in different structures MAY be exempted if refactoring introduces significant risk (EX-001).
- **R-COLOCATED-009** MAY: Cross-cutting integration tests MAY be exempted if they require access to multiple package internals (EX-002).

### Verify

```bash
# Verify no .spec.tsx files exist outside __tests__ directories
find packages/core -name '*.spec.tsx' -not -path '*/__tests__/*' | wc -l | grep -q '^0$'

# Verify Jest configuration includes __tests__ in test discovery
grep -r "testMatch" jest.config.* | grep -q "__tests__"

# Verify baseline of co-located test files
find packages/core/__tests__ -name '*.spec.tsx' | wc -l

# Verify TypeScript excludes test files from production
grep -q "exclude.*__tests__" tsconfig.json
grep -q "exclude.*\.spec\.tsx" tsconfig.json

# Verify build configuration excludes test patterns
grep -r "__tests__" build.config.* || grep -r "exclude.*__tests__" webpack.config.* || grep -r "exclude.*__tests__" vite.config.*
```

**Accept when:**
- All .spec.tsx test files in packages/core are located within __tests__ directories
- Jest or test runner configuration includes __tests__ in test discovery patterns (testMatch: ['**/__tests__/**/*.spec.tsx'])
- Build configuration explicitly excludes __tests__ directories and .spec.tsx files from production bundles
- TypeScript configuration excludes test files from production builds
- At least 10 test files follow the co-located __tests__ pattern (current baseline)
- No test files are found outside __tests__ directories in packages/core
- ESLint rules prevent imports from __tests__ directories in production code

Claude Code MUST verify all R-COLOCATED rules before accepting test file organization in packages/core. Verification is mandatory and MUST NOT be skipped or deferred. CI pipeline MUST fail if test files are found outside __tests__ directories. Pull requests MUST be blocked until tests are moved to correct locations.
</enforcement>
