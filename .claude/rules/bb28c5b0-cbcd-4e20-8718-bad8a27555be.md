<rule_activation id="bb28c5b0-cbcd-4e20-8718-bad8a27555be" title="Standardize Logging and Observability Configuration in Runtime Environments: Runtime Environment Detection" applies_to="**/*">
These rules are ALWAYS ACTIVE for all TypeScript/JavaScript runtime components including libraries, servers, CLI tools, and development tooling that generates or scaffolds runtime configuration.
</rule_activation>

### Rules

- **R-LOG-001** SHOULD: Runtime environment detection logic SHOULD be centralized in dedicated configuration modules to avoid duplication.

### Verify

```bash
# Count direct console usage in TypeScript and JavaScript files
grep -r 'console\.(log|error|warn)' --include='*.ts' --include='*.js' packages/ recipes/ | wc -l

# Verify environment variable usage for logging configuration
grep -r 'process\.env\.LOG_LEVEL\|process\.env\.NODE_ENV' --include='*.ts' --include='*.js' packages/ recipes/ | wc -l

# Check ESLint enforcement of no-console rule
npm run lint -- --rule 'no-console: error' 2>&1 | grep -c 'no-console'
```

**Accept when:**
- All components in packages/ and recipes/ directories use environment-based logging configuration rather than hardcoded console statements
- Grep for environment variable usage (LOG_LEVEL, NODE_ENV) returns matches in at least 80% of runtime components
- Linting rules enforce structured logging patterns and flag direct console usage in production code paths

<enforcement>
Claude Code MUST NOT skip or defer verification. Automated CI pipeline checks using ESLint rules for console usage and logging patterns are mandatory. Code review must verify proper logging configuration in new components. Violations result in CI pipeline failure and code review blocks.
</enforcement>
