<rule_activation id="6d7d793f-261e-4eb8-a525-75bb0e638e45" title="Implement Structured Server-Side Logging with Cache Layer Integration in Remix Applications: Server Side Logging" applies_to="**/entry.server.tsx">
These rules are ALWAYS ACTIVE for all Remix server entry points (entry.server.tsx) that handle server-side rendering and request processing.
</rule_activation>

### Rules

- **R-SSR-LOG-001** MUST: Server-side logging MUST integrate with the cache layer to track cache hits, misses, and invalidations.

### Verify

```bash
# Check for logging statements in entry.server.tsx
grep -r 'entry.server.tsx' --include='*.tsx' -A 20 | grep -E '(log|logger|console)' | head -10

# Check for cache and logging integration
grep -r 'cache.*log\|log.*cache' --include='*.tsx' --include='*.ts' recipes/

# Find all entry.server.tsx files with request handling
find . -name 'entry.server.tsx' -exec grep -l 'handleRequest\|renderToString' {} \;
```

**Accept when:**
- entry.server.tsx files contain logging statements that capture request processing events
- Cache layer operations are instrumented with logging that tracks hits, misses, or cache state
- Log output includes structured data (request context, timing, cache metrics) rather than plain console.log statements
- A structured logging library (e.g., pino, winston) is configured with JSON output support
- Log levels are appropriately configured (INFO for successful requests, WARN for cache misses or slow renders, ERROR for exceptions)

Claude Code MUST NOT skip or defer verification. All entry.server.tsx files MUST be checked for structured logging integration with cache layer metrics before approval.
</enforcement>
