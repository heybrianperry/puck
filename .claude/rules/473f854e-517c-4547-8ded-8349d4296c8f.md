<rule_activation id="473f854e-517c-4547-8ded-8349d4296c8f" title="Implement Console Logging with Conditional Debug Output for Development Observability: Production Builds Strip" applies_to="**/*">
These rules are ALWAYS ACTIVE for all frontend components, React components, client-side JavaScript and TypeScript code, and build-time logging configuration.
</rule_activation>

### Rules

- **R-CONSOLE-001** SHOULD: Production builds SHOULD strip or disable console logging statements through build optimization tools (e.g., terser, babel plugins) to reduce bundle size.
- **R-CONSOLE-002** MUST: Use environment variable checks (e.g., `process.env.NODE_ENV !== 'production'`) to conditionally execute logging statements.
- **R-CONSOLE-003** MUST: Configure build tools to strip console statements in production builds (e.g., terser config with `drop_console: true`).
- **R-CONSOLE-004** MUST: Create and use a sanitization utility function that removes or redacts sensitive fields from objects before logging.
- **R-CONSOLE-005** SHOULD: Prefix log messages with component or module names for easier filtering (e.g., `console.log('[ComponentName]', message)`).
- **R-CONSOLE-006** MAY: Use `console.group/console.groupEnd` for related log messages to improve readability in complex operations.
- **R-CONSOLE-007** MUST: Never log sensitive information such as API keys, tokens, passwords, secrets, or user credentials to console.
- **R-CONSOLE-008** SHOULD: Use `console.warn` and `console.error` for important messages instead of `console.log` to reduce noise.

### Verify

```bash
# Scan for console statements containing sensitive data patterns
grep -r "console\.log.*token\|console\.log.*password\|console\.log.*secret\|console\.log.*apiKey" --include="*.ts" --include="*.tsx" --include="*.js" --include="*.jsx" .

# Verify production builds have console statements stripped
NODE_ENV=production npm run build && grep -r "console\.log\|console\.warn" dist/ || echo 'No console statements in production build'

# Verify ESLint configuration for console usage
eslint . --ext .ts,.tsx,.js,.jsx --rule 'no-console: [error, { allow: [warn, error] }]'
```

**Accept when:**
- No console logging statements contain sensitive data patterns (token, password, secret, apiKey, credentials) as verified by grep scan
- Production builds have all `console.log` statements removed or disabled as verified by bundle inspection
- ESLint or similar linting tools are configured to warn or error on `console.log` usage in production code paths
- All console statements in development code are wrapped in environment guards (`process.env.NODE_ENV !== 'production'`)
- Build process verification confirms production bundles have console statements stripped
- Code review checklist includes verification that new logging statements are conditional and don't contain sensitive data
