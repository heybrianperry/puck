<rule_activation id="9ce406de-970a-4b84-98d9-700eafcdc511" title="Implement Cache Layer for Configuration and Environment Data: Cache Implementations Not" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime environments and configuration management systems. All components that handle configuration data or environment variables MUST comply with the caching requirements specified herein.
</rule_activation>

### Rules

- **R-CACHE-001** MUST_NOT: Cache implementations MUST NOT cache sensitive credentials or secrets without proper encryption at rest.
- **R-CACHE-002** MUST: Use a singleton pattern or module-level cache to ensure configuration is cached once per application instance.
- **R-CACHE-003** SHOULD: Implement cache warming during application startup to avoid cold start penalties on first requests.
- **R-CACHE-004** SHOULD: Consider using a Map or WeakMap for cache storage to enable efficient lookups and automatic garbage collection.
- **R-CACHE-005** SHOULD: Add instrumentation to track cache hit rates, miss rates, and access patterns for performance monitoring.
- **R-CACHE-006** SHOULD: Document which configuration values are cached and their refresh policies in the application's operational runbook.
- **R-CACHE-007** MUST: Implement cache invalidation hooks triggered by configuration file changes or environment variable updates.
- **R-CACHE-008** MUST: Implement strict filtering to prevent caching of sensitive data patterns.
- **R-CACHE-009** MUST: Implement cache size limits and eviction policies to prevent memory exhaustion.

### Verify

```bash
# Check for cache and config patterns in TypeScript/JavaScript files
grep -r 'cache.*config\|config.*cache' --include='*.ts' --include='*.tsx' --include='*.js' --include='*.jsx' .

# Check for cached environment variable access
grep -r 'process\.env' --include='*.ts' --include='*.tsx' | grep -c 'cache\|memo' || echo 'No cached env access found'

# Run cache configuration tests
npm test -- --grep 'cache.*configuration|configuration.*cache'
```

**Accept when:**
- Configuration access code demonstrates caching mechanism with evidence of in-memory storage
- Cache invalidation or refresh logic is present and tested
- No direct process.env access in hot paths without caching layer
- Performance tests show reduced configuration access latency compared to uncached baseline
- Sensitive data filtering is implemented and verified
- Cache size limits and eviction policies are documented and enforced
- Cache hit rates and performance metrics are instrumented and monitored

<enforcement>
Claude Code MUST verify all configuration caching implementations against these rules. Violations of R-CACHE-001 (sensitive data caching) and R-CACHE-002 (singleton pattern) are non-negotiable. Performance regression or stale configuration risks require mitigation before acceptance.
</enforcement>
