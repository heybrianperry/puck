<rule_activation id="c1512b55-93b2-485b-9c67-eaecc7eddc46" title="Adopt Explicit Export Pattern for Library Module Public APIs: Modules Export Dependencies" applies_to="packages/core/lib/**/*.ts packages/core/lib/**/*.tsx packages/core/components/**/*.ts packages/core/components/**/*.tsx">
These rules are ALWAYS ACTIVE for all public-facing modules under packages/core/lib/ and packages/core/components/.
</rule_activation>

### Rules

- **R-EXP-001** MAY: Modules MAY re-export dependencies to provide a stable facade over third-party libraries.
- **R-EXP-002** MUST: All public-facing modules under packages/core/lib and packages/core/components have explicit export statements.
- **R-EXP-003** MUST: No internal helper functions or private utilities are exported from public API modules.
- **R-EXP-004** MUST: Server-specific modules use .server.tsx extension and are not imported in client-side code.
- **R-EXP-005** SHOULD: Use TypeScript's 'export type' for type-only exports to prevent runtime inclusion in bundles.
- **R-EXP-006** SHOULD: Establish naming conventions: index.tsx for component exports, descriptive names for utilities (e.g., flatten-data.ts, populate-ids.ts).
- **R-EXP-007** SHOULD: Document public APIs in a centralized API reference, generated from TSDoc comments on exported members.

### Verify

```bash
# Count explicit export statements in public modules
grep -r 'export {' packages/core/lib packages/core/components | wc -l

# Find all index files (entry points)
find packages/core -name 'index.tsx' -o -name 'index.ts' | wc -l

# Run API Extractor to detect breaking changes
npx api-extractor run --local || echo 'API surface check'

# Verify server-specific modules use correct extension
grep -r '\.server\.' packages/core/components | grep -v node_modules
```

**Accept when:**
- All public-facing modules under packages/core/lib and packages/core/components have explicit export statements
- No internal helper functions or private utilities are exported from public API modules
- Server-specific modules use .server.tsx extension and are not imported in client-side code
- Package.json exports field restricts access to only intended public modules
- API Extractor runs successfully without detecting unintended breaking changes
- No linter warnings for modules missing explicit exports in public directories
