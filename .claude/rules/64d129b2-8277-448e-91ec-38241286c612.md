<rule_activation id="64d129b2-8277-448e-91ec-38241286c612" title="Adopt Modular Library Architecture with Core Package Pattern: Library Modules Export" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the codebase to enforce modular library architecture with clear separation between core packages and application-specific code.
</rule_activation>

### Rules

- **R-CORE-001** MAY: Library modules MAY export configuration objects (e.g., default-viewports.ts) alongside their component implementations.
- **R-CORE-002** MUST: Core packages MUST NOT import from application-specific directories (e.g., recipes/).
- **R-CORE-003** MUST: Reusable utility functions and data transformation logic MUST be placed in packages/core/lib.
- **R-CORE-004** MUST: Reusable UI components intended for use across multiple features MUST be placed in packages/core/components.
- **R-CORE-005** MUST: Custom React hooks that encapsulate reusable stateful logic MUST be placed in packages/core/lib.
- **R-CORE-006** MUST NOT: Application-specific business logic and feature implementations MUST NOT be placed in core packages.
- **R-CORE-007** MUST NOT: Route handlers and API endpoints specific to individual applications MUST NOT be placed in core packages.
- **R-CORE-008** MUST NOT: One-off components used in a single feature without reuse potential MUST NOT be placed in core packages.
- **R-CORE-009** SHOULD: Components SHOULD be used in at least 2-3 places before promotion to core.
- **R-CORE-010** SHOULD: Server-side rendering implementations of core components SHOULD have corresponding server.tsx implementations.

### Verify

```bash
# Count utility modules in core/lib
find packages/core/lib -type f \( -name '*.ts' -o -name '*.tsx' \) | wc -l

# Count components in core/components
find packages/core/components -type f -name 'index.tsx' | wc -l

# Verify no application imports in core packages
grep -r 'from.*recipes/' packages/core/ && echo 'ERROR: Core package imports from application code' || echo 'OK: No application imports in core'

# Verify build config exists
test -f packages/tsup-config/react-import.js && echo 'OK: Build config exists' || echo 'ERROR: Missing build config'

# Detect circular dependencies
dependency-cruiser --validate .dependency-cruiser.js packages/core/ 2>/dev/null || echo 'Run dependency-cruiser for circular dependency analysis'
```

**Accept when:**
- Core package contains multiple utility modules in lib directory and multiple components in components directory
- No imports from application-specific directories (e.g., recipes/) are found in core package files
- Build configuration for library packages exists in a centralized location (packages/tsup-config/)
- Components that require server-side rendering have corresponding server.tsx implementations
- Dependency analysis shows no circular dependencies between core packages and application code
- All reusable code follows established naming conventions (packages/core/lib for utilities, packages/core/components for UI)

<enforcement>
Claude Code MUST verify all rules before approving changes to core packages or application imports. Violations of R-CORE-002, R-CORE-003, R-CORE-004, R-CORE-005, R-CORE-006, R-CORE-007, and R-CORE-008 MUST block CI and require remediation. Code review MUST check rule compliance before merge.
</enforcement>
