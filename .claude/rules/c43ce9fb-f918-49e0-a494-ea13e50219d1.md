<rule_activation id="c43ce9fb-f918-49e0-a494-ea13e50219d1" title="Adopt Remix Route-Based Configuration Pattern for Service Boundaries: Route Modules Define" applies_to="app/routes/**/*.tsx">
These rules are ALWAYS ACTIVE for all Remix route modules. Route modules MUST define service boundaries explicitly through configuration objects or dependency injection at the route level to ensure proper isolation and configuration management across different application contexts.
</rule_activation>

### Rules

- **R-REMIX-001** MUST: Route modules MUST define service boundaries explicitly through configuration objects or dependency injection at the route level.
- **R-REMIX-002** MUST: Service configuration objects MUST be defined within loader or action functions, not in component code.
- **R-REMIX-003** MUST: Environment variable access MUST only occur within loader and action functions, never in route component code.
- **R-REMIX-004** SHOULD: Use TypeScript interfaces to define configuration shapes and ensure consistency across routes.
- **R-REMIX-005** SHOULD: Implement loader functions that return configuration objects alongside data, making dependencies explicit in the route's data contract.

### Verify

```bash
# Check that all route modules with service dependencies define configuration objects
grep -r 'export.*loader' app/routes/ | xargs -I {} sh -c 'grep -L "config" {} || echo "Missing config in: {}"'

# Find direct process.env access outside of loader/action functions
find app/routes -name '*.tsx' -exec grep -l 'process\.env\.' {} \; | grep -v 'loader\|action'

# Verify TypeScript compilation and linting
npm run type-check && npm run lint -- --rule 'no-process-env: error' app/routes/
```

**Accept when:**
- All route modules with service dependencies define configuration objects within loader or action functions
- No direct process.env access exists in route component code (only in loaders/actions)
- TypeScript compilation succeeds with strict mode enabled for all route modules
- Code review checklist confirms service boundaries are explicitly defined for new routes
- ESLint rules preventing direct environment variable access in components pass
- Automated tests verify configuration isolation between routes

<enforcement>
Claude Code MUST NOT skip or defer verification. All route modules must pass the verification commands before acceptance. Violations trigger CI pipeline failure and require architecture review for any exceptions.
</enforcement>
