<rule_activation id="258b4eb0-db09-4ba1-8b2b-f94a5b22c7b9" title="Implement Console Logging with Conditional Debug Output for Development Observability: Teams Implement Structured" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. Console logging must be conditional, sanitized, and stripped from production builds.
</rule_activation>

### Rules

- **R-CONSOLE-001** MAY: Teams MAY implement structured logging wrappers that provide consistent formatting and automatic sanitization of sensitive data.
- **R-CONSOLE-002** MUST: Use environment variable checks (e.g., `process.env.NODE_ENV !== 'production'`) to conditionally execute logging statements.
- **R-CONSOLE-003** MUST: Configure build tools to strip console statements in production builds (e.g., terser with `drop_console: true`).
- **R-CONSOLE-004** MUST: Create and use a sanitization utility function that removes or redacts sensitive fields (token, password, secret, apiKey, credentials) before logging.
- **R-CONSOLE-005** SHOULD: Prefix log messages with component or module names for easier filtering (e.g., `console.log('[ComponentName]', message)`).
- **R-CONSOLE-006** SHOULD: Use `console.group/console.groupEnd` for related log messages to improve readability in complex operations.
- **R-CONSOLE-007** MUST: Never log sensitive data including API keys, tokens, passwords, secrets, PII, or credentials to console.
- **R-CONSOLE-008** SHOULD: Prefer `console.warn` and `console.error` for important messages over `console.log`.
- **R-CONSOLE-009** MUST: Configure ESLint with `no-console` rules to warn or error on console usage in production code paths.

### Verify

```bash
# Scan for console statements containing sensitive data patterns
grep -r "console\.log.*token\|console\.log.*password\|console\.log.*secret\|console\.log.*apiKey" --include="*.ts" --include="*.tsx" --include="*.js" --include="*.jsx" .

# Verify production builds have console statements stripped
NODE_ENV=production npm run build && grep -r "console\.log\|console\.warn" dist/ || echo 'No console statements in production build'

# Verify ESLint configuration for no-console rules
eslint . --ext .ts,.tsx,.js,.jsx --rule 'no-console: [error, { allow: [warn, error] }]' --env-info
```

**Accept when:**
- No console logging statements contain sensitive data patterns (token, password, secret, apiKey, credentials) as verified by grep scan
- Production builds have all `console.log` statements removed or disabled as verified by bundle inspection
- ESLint or similar linting tools are configured to warn or error on console usage in production code paths
- All logging statements are wrapped in environment guards (e.g., `if (process.env.NODE_ENV !== 'production')`)
- A sanitization utility function exists and is used for all objects logged to console
- Code review checklist includes verification that new logging statements are conditional and don't contain sensitive data
