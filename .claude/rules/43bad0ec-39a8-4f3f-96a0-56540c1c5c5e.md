<rule_activation id="43bad0ec-39a8-4f3f-96a0-56540c1c5c5e" title="Adopt Modular Library Architecture with Core Package Pattern: Build Configuration Library" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the codebase to enforce modular library architecture with clear separation between core packages and application-specific code.
</rule_activation>

### Rules

- **R-MODULAR-001** SHOULD: Build configuration for library packages SHOULD be centralized in dedicated config packages (e.g., packages/tsup-config).
- **R-MODULAR-002** MUST: Core packages (packages/core/lib and packages/core/components) MUST NOT import from application-specific directories (e.g., recipes/).
- **R-MODULAR-003** SHOULD: Reusable utility functions, data transformation logic, and UI components SHOULD be placed in core packages rather than duplicated across features.
- **R-MODULAR-004** SHOULD: Custom React hooks that encapsulate reusable stateful logic SHOULD be located in packages/core/lib.
- **R-MODULAR-005** SHOULD: Server-side rendering implementations of core components SHOULD have corresponding server.tsx implementations.
- **R-MODULAR-006** MUST: Application-specific business logic, route handlers, API endpoints, and one-off components MUST NOT be placed in core packages.
- **R-MODULAR-007** SHOULD: Components SHOULD be promoted to core only after being used in at least 2-3 places to avoid premature abstraction.
- **R-MODULAR-008** MUST: Circular dependencies between core packages and application code MUST be prevented through linting and architectural enforcement.

### Verify

```bash
# Count utility modules in core/lib
find packages/core/lib -type f \( -name '*.ts' -o -name '*.tsx' \) | wc -l

# Count components in core/components
find packages/core/components -type f -name 'index.tsx' | wc -l

# Verify no application imports in core packages
grep -r 'from.*recipes/' packages/core/ && echo 'ERROR: Core package imports from application code' || echo 'OK: No application imports in core'

# Verify build config exists
test -f packages/tsup-config/react-import.js && echo 'OK: Build config exists' || echo 'ERROR: Missing build config'

# Detect circular dependencies
dependency-cruiser --validate .dependency-cruiser.js packages/core packages/
```

**Accept when:**
- Core package contains multiple utility modules in lib directory and multiple components in components directory
- No imports from application-specific directories (e.g., recipes/) are found in core package files
- Build configuration for library packages exists in a centralized location (packages/tsup-config)
- Components that require server-side rendering have corresponding server.tsx implementations
- No circular dependencies are detected between core packages and application code
- Linting rules pass without violations of import path restrictions
