<rule_activation id="08654f7e-6384-41d6-be4a-5d38937bd509" title="Adopt TypeScript Configuration Export Pattern for Public API Packages: Public Contracts Remain" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching public API packages under /packages/*, API route handlers, and shared configuration packages.
</rule_activation>

### Rules

- **R-TSCONFIG-001** SHOULD: Public API contracts SHOULD remain framework-agnostic where possible, with framework-specific adapters provided separately.
- **R-TSCONFIG-002** MUST: All public packages under /packages/* intended for external consumption MUST contain either tsup.config.ts or equivalent build configuration.
- **R-TSCONFIG-003** MUST: Package.json files for public packages MUST define explicit exports field with type definitions.
- **R-TSCONFIG-004** SHOULD: Use the shared tsup-config package as the foundation for all new public packages to ensure consistency.
- **R-TSCONFIG-005** SHOULD: Define package.json exports field with explicit entry points for main, types, and any conditional exports (import/require).
- **R-TSCONFIG-006** SHOULD: Include both ESM and CJS outputs when necessary for broader compatibility, but prefer ESM as the primary format.
- **R-TSCONFIG-007** SHOULD: Document public API surface in README files and consider using API Extractor or similar tools to generate API documentation.
- **R-TSCONFIG-008** SHOULD: For API route handlers, follow the established naming pattern (api.*.tsx) to make external interfaces immediately recognizable.
- **R-TSCONFIG-009** SHOULD: Leverage TypeScript's declaration maps for better debugging experience in consumer projects.
- **R-TSCONFIG-010** MUST: API route handlers in recipe/example applications that demonstrate public API usage MUST follow consistent naming conventions (api.* or routes/api/*).

### Verify

```bash
# Count tsup.config.ts files in packages
grep -r "tsup.config.ts" packages/*/tsup.config.ts | wc -l

# Count package.json files with exports field
find packages -name 'package.json' -exec jq -e '.exports' {} \; 2>/dev/null | wc -l

# Count explicit exports from index.ts files
grep -r "export.*from" packages/*/index.ts | grep -v "// internal" | wc -l
```

**Accept when:**
- All public packages under /packages/* contain either tsup.config.ts or equivalent build configuration
- Package.json files for public packages define explicit exports field with type definitions
- API route handlers follow consistent naming conventions (api.* or routes/api/*) across recipe applications
- Shared build configuration (tsup-config) is used by at least 80% of public packages
- Automated CI checks using publint or package-lint verify export configurations
- TypeScript compilation checks ensure type definitions are properly generated and exported
