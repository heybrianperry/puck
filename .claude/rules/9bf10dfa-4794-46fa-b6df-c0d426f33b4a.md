<rule_activation id="9bf10dfa-4794-46fa-b6df-c0d426f33b4a" title="Enforce Input Validation and Boundary Checking for Configuration Parameters" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime configuration and environment management code. All configuration parameter handling MUST comply with the input validation rules defined herein.
</rule_activation>

### Rules

- **R-CFG-001** SHOULD: Configuration parameters SHOULD have documented default values that are used when optional parameters are not provided.
- **R-CFG-002** MUST: All direct accesses to external configuration sources (environment variables, API requests, user input, file system operations, query strings) MUST be wrapped in validation functions that check type and range.
- **R-CFG-003** MUST: Numeric parsing operations (parseInt, parseFloat, Number) MUST be followed by boundary checks or NaN/Infinity validation.
- **R-CFG-004** SHOULD: Validation SHOULD be implemented at the earliest possible point in the data flow, ideally immediately after reading from external sources.
- **R-CFG-005** SHOULD: Clear, actionable error messages SHOULD include the parameter name, received value, expected format, and valid range.
- **R-CFG-006** SHOULD: Validated configuration values SHOULD be cached to avoid repeated validation overhead, especially for environment variables that don't change during runtime.
- **R-CFG-007** SHOULD: Schema validation libraries (Zod, Yup, Joi) SHOULD be considered to define configuration schemas declaratively and generate TypeScript types from schemas.

### Verify

```bash
# Check for unvalidated environment variable access
grep -r 'process\.env\[' --include='*.ts' --include='*.tsx' --include='*.js' | grep -v 'validate\|check\|parse' | wc -l

# Check for unvalidated numeric parsing
grep -r 'parseInt\|parseFloat\|Number(' --include='*.ts' --include='*.tsx' | grep -v 'isNaN\|isFinite\|>\|<\|throw' | head -20

# Run validation test suite
npm test -- --grep 'validation|config' || echo 'No validation tests found'
```

**Accept when:**
- All direct accesses to process.env are wrapped in validation functions that check type and range
- Numeric parsing operations (parseInt, parseFloat, Number) are followed by boundary checks or NaN/Infinity validation
- Test suite includes validation test cases for configuration parameters covering valid, invalid, and edge case inputs
- Configuration parameters from external sources include documented default values
- Validation is performed at the earliest point in the data flow after reading from external sources
- Error messages for validation failures include parameter name, received value, expected format, and valid range

<enforcement>
Claude Code MUST NOT skip or defer verification. All configuration parameter handling MUST comply with these rules. Violations in production code require security review. Exceptions require explicit documentation linking to this ADR and tech lead approval.
</enforcement>
