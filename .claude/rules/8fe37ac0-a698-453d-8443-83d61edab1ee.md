<rule_activation id="8fe37ac0-a698-453d-8443-83d61edab1ee" title="Adopt Jest and React Testing Library for Component Testing: Test Suites Use" applies_to="**/*">
These rules are ALWAYS ACTIVE for all test files in the packages/core directory and related TypeScript utility tests.
</rule_activation>

### Rules

- **R-JEST-001** MUST: Test suites MUST use Jest as the test runner and assertion framework.
- **R-JEST-002** MUST: All React component tests in packages/core directory MUST use Jest.
- **R-JEST-003** MUST: All TypeScript utility function tests in packages/core/lib directory MUST use Jest.
- **R-JEST-004** MUST: Data transformation and resolver function tests MUST use Jest.
- **R-JEST-005** MUST: Reducer and action tests for state management logic MUST use Jest.
- **R-JEST-006** MUST: Integration tests involving multiple components or modules MUST use Jest.
- **R-JEST-007** MUST: Test files MUST use .spec.tsx or .spec.ts extensions.
- **R-JEST-008** MUST: Test files MUST be located in __tests__ directories co-located with source code.
- **R-JEST-009** SHOULD: React component tests SHOULD use @testing-library/react for rendering and queries.
- **R-JEST-010** SHOULD: Jest SHOULD be configured with TypeScript support using ts-jest or @swc/jest.
- **R-JEST-011** SHOULD: Shared test helpers and fixtures SHOULD be created in __helpers__ directories.
- **R-JEST-012** SHOULD: Jest coverage thresholds SHOULD be configured in jest.config.js.
- **R-JEST-013** SHOULD: Snapshots SHOULD be used sparingly and only for stable serialized output.
- **R-JEST-014** MAY: End-to-end tests MAY use a separate E2E framework (out of scope for Jest requirement).
- **R-JEST-015** MAY: Performance benchmarking tests MAY use dedicated performance testing tools (out of scope).
- **R-JEST-016** MAY: Visual regression tests MAY use dedicated visual testing tools (out of scope).

### Verify

```bash
# Count test files using describe/it/test patterns
grep -r "describe\|it\|test" packages/core/**/__tests__/**/*.spec.tsx | wc -l

# Count __tests__ directories
find packages/core -type d -name '__tests__' | wc -l

# Verify React Testing Library usage
grep -r "@testing-library/react" packages/core/**/__tests__/**/*.spec.tsx | wc -l

# List all test files with correct extensions
npm test -- --listTests | grep -E '\.spec\.(tsx|ts)$' | wc -l

# Run Jest test suite
npm test

# Check Jest configuration exists
test -f jest.config.js && echo "Jest config found"

# Verify coverage reports
npm test -- --coverage
```

**Accept when:**
- All test files use .spec.tsx or .spec.ts extensions and are located in __tests__ directories
- Jest is configured as the test runner and all tests execute successfully with 'npm test'
- React component tests import and use @testing-library/react for rendering and queries
- Test coverage reports are generated successfully and meet minimum threshold requirements
- Jest configuration includes TypeScript support via ts-jest or @swc/jest
- Module name mappings in jest.config.js match TypeScript path aliases
- All test files follow the established naming and location conventions
