<rule_activation id="0538f0ee-7b02-45bc-8a82-12b3c2a45496" title="Standardize Logging and Observability Configuration in Runtime Environments: Logging Configuration Not" applies_to="**/*">
These rules are ALWAYS ACTIVE for all TypeScript/JavaScript runtime components (libraries, servers, CLI tools), environment variable configuration for logging, and observability infrastructure.
</rule_activation>

### Rules

- **R-LOG-001** MUST_NOT: Logging configuration MUST NOT expose sensitive environment variables or credentials in log output

### Verify

```bash
# Count direct console usage in TypeScript/JavaScript files
grep -r 'console\.(log|error|warn)' --include='*.ts' --include='*.js' packages/ recipes/ | wc -l

# Verify environment-based logging configuration usage
grep -r 'process\.env\.LOG_LEVEL\|process\.env\.NODE_ENV' --include='*.ts' --include='*.js' packages/ recipes/ | wc -l

# Check ESLint enforcement of no-console rule
npm run lint -- --rule 'no-console: error' 2>&1 | grep -c 'no-console'
```

**Accept when:**
- All components in packages/ and recipes/ directories use environment-based logging configuration rather than hardcoded console statements
- Grep for environment variable usage (LOG_LEVEL, NODE_ENV) returns matches in at least 80% of runtime components
- Linting rules enforce structured logging patterns and flag direct console usage in production code paths
- No sensitive environment variables or credentials appear in log output across all runtime contexts

<enforcement>
Claude Code MUST NOT skip or defer verification of logging configuration compliance. Violations detected by automated CI pipeline checks, code review checklists, and periodic architecture audits MUST be addressed before merge.
</enforcement>
