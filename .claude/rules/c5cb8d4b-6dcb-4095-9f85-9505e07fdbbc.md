<rule_activation id="c5cb8d4b-6dcb-4095-9f85-9505e07fdbbc" title="Adopt Explicit Export Pattern for Library Module Public APIs: Public Modules Organized" applies_to="packages/core/lib/**/*,packages/core/components/**/*">
These rules are ALWAYS ACTIVE for all public API modules under packages/core/lib/ and packages/core/components/.
</rule_activation>

### Rules

- **R-EXPORT-001** MUST: Public API modules MUST be organized in a clear directory structure that distinguishes between public exports (lib/, components/) and internal implementation.
- **R-EXPORT-002** MUST: All public-facing modules under packages/core/lib and packages/core/components have explicit export statements.
- **R-EXPORT-003** MUST: No internal helper functions or private utilities are exported from public API modules.
- **R-EXPORT-004** MUST: Server-specific modules use .server.tsx extension and are not imported in client-side code.
- **R-EXPORT-005** SHOULD: Use TypeScript's 'export type' for type-only exports to prevent runtime inclusion in bundles.
- **R-EXPORT-006** SHOULD: Establish naming conventions: index.tsx for component exports, descriptive names for utilities (e.g., flatten-data.ts, populate-ids.ts).
- **R-EXPORT-007** SHOULD: Document public APIs in a centralized API reference, generated from TSDoc comments on exported members.
- **R-EXPORT-008** MAY: Use API Extractor or similar tools to generate API reports and detect unintentional breaking changes.

### Verify

```bash
# Count explicit export statements in public modules
grep -r 'export {' packages/core/lib packages/core/components | wc -l

# Find all index files (entry points)
find packages/core -name 'index.tsx' -o -name 'index.ts' | wc -l

# Run API Extractor to check API surface
npx api-extractor run --local || echo 'API surface check'

# Verify server-specific modules use correct extension
grep -r '\.server\.' packages/core/components | grep -v node_modules
```

**Accept when:**
- All public-facing modules under packages/core/lib and packages/core/components have explicit export statements
- No internal helper functions or private utilities are exported from public API modules
- Server-specific modules use .server.tsx extension and are not imported in client-side code
- Package.json exports field restricts access to only intended public modules

<enforcement>
Claude Code MUST verify all rules before accepting changes to public API modules. Verification is mandatory and MUST NOT be skipped or deferred. CI pipeline MUST run API Extractor to detect breaking changes. Code review MUST verify export declarations and documentation.
</enforcement>
