<rule_activation id="b3995f5b-9874-4a44-a03d-765fc2adf8c1" title="Standardize Jest Testing Framework with React Testing Library for Component Tests: Tests Executable Pipeline" applies_to="**/*">
These rules are ALWAYS ACTIVE for all test file creation and maintenance within the CI/CD pipeline.
</rule_activation>

### Rules

- **R-JEST-001** MUST: All tests MUST be executable in the CI/CD pipeline without manual intervention.
- **R-JEST-002** MUST: All test files MUST use .spec.tsx or .spec.ts extensions and be located in __tests__ directories.
- **R-JEST-003** MUST: Jest configuration MUST be present in package.json or jest.config.js files.
- **R-JEST-004** MUST: React Testing Library MUST be listed as a dependency in packages containing React component tests.
- **R-JEST-005** SHOULD: Establish coverage thresholds (e.g., 80% for statements, branches, functions, and lines) and enforce them in CI/CD.
- **R-JEST-006** SHOULD: Create shared testing utilities package with common mocks, test helpers, and custom matchers to promote consistency.
- **R-JEST-007** SHOULD: Use React Testing Library patterns for user-centric testing rather than implementation details.
- **R-JEST-008** SHOULD: Set up pre-commit hooks to run tests on changed files to catch issues early.
- **R-JEST-009** MAY: Legacy test files using alternative frameworks may remain until scheduled refactoring (EXC-001).
- **R-JEST-010** MAY: Specialized testing scenarios requiring framework-specific features not available in Jest may use alternatives (EXC-002).

### Verify

```bash
# Verify Jest test files exist with correct naming convention
grep -r "describe\|it\|test" packages/*/lib/**/__tests__/*.spec.tsx | head -5

# Find all test files with correct extensions
find packages -type f -name '*.spec.tsx' -o -name '*.spec.ts' | head -10

# Verify React Testing Library is a dependency
grep -r "@testing-library/react" packages/*/package.json

# List all executable tests
npm test -- --listTests | grep __tests__
```

**Accept when:**
- All test files use .spec.tsx or .spec.ts extensions and are located in __tests__ directories
- Jest configuration is present in package.json or jest.config.js files
- React Testing Library is listed as a dependency in packages containing React component tests
- Tests execute successfully in CI/CD pipeline without manual intervention

Claude Code MUST NOT skip or defer verification. All tests MUST be executable in the CI/CD pipeline without manual intervention. Pull requests without tests or with failing tests are blocked from merging. Coverage drops below threshold trigger CI/CD failure and require remediation.
</enforcement>
