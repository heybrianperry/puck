<rule_activation id="b60403d5-4156-4bd1-83a1-dfcfb752e605" title="Adopt Explicit Export Pattern for Library Module Public APIs: Custom Hooks Prefixed" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in packages/core/lib/, packages/core/components/, and public-facing modules to enforce explicit export patterns and maintain stable public API contracts.
</rule_activation>

### Rules

- **R-EXPORT-001** SHOULD: Custom hooks SHOULD be prefixed with 'use-' and exported from dedicated module files.
- **R-EXPORT-002** SHOULD: Use TypeScript's 'export type' for type-only exports to prevent runtime inclusion in bundles.
- **R-EXPORT-003** SHOULD: Establish naming conventions: index.tsx for component exports, descriptive names for utilities (e.g., flatten-data.ts, populate-ids.ts).
- **R-EXPORT-004** SHOULD: For server-specific modules, use .server.tsx extension and configure bundler to exclude from client builds.
- **R-EXPORT-005** SHOULD: Document public APIs in a centralized API reference, generated from TSDoc comments on exported members.
- **R-EXPORT-006** MUST: All public-facing modules under packages/core/lib and packages/core/components have explicit export statements.
- **R-EXPORT-007** MUST: No internal helper functions or private utilities are exported from public API modules.
- **R-EXPORT-008** MUST: Server-specific modules use .server.tsx extension and are not imported in client-side code.
- **R-EXPORT-009** MUST: Package.json exports field restricts access to only intended public modules.

### Verify

```bash
# Count explicit export statements in public modules
grep -r 'export {' packages/core/lib packages/core/components | wc -l

# Find all index files (component and utility entry points)
find packages/core -name 'index.tsx' -o -name 'index.ts' | wc -l

# Run API Extractor to detect breaking changes and unintended exports
npx api-extractor run --local || echo 'API surface check'

# Verify server-specific modules use correct naming convention
grep -r '\.server\.' packages/core/components | grep -v node_modules

# Verify custom hooks follow use- prefix convention
grep -r 'export.*use[A-Z]' packages/core/lib packages/core/components

# Check package.json exports field is properly configured
grep -A 20 '"exports"' package.json
```

**Accept when:**
- All public-facing modules under packages/core/lib and packages/core/components have explicit export statements
- No internal helper functions or private utilities are exported from public API modules
- Server-specific modules use .server.tsx extension and are not imported in client-side code
- Package.json exports field restricts access to only intended public modules
- All custom hooks are prefixed with 'use-' and exported from dedicated module files
- API Extractor runs successfully with no unintended breaking changes detected
- TypeScript type-only exports use 'export type' syntax
- TSDoc comments document all exported public members
