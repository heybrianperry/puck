<rule_activation id="da5401ff-e406-4ce7-b8b3-829579659da0" title="Adopt Console-Based Logging for Development and Debugging: Applications Wrap Console" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. Console-based logging is the standard approach for development and debugging across client-side and server-side code without introducing heavy logging dependencies.
</rule_activation>

### Rules

- **R-CONSOLE-001** MAY: Applications MAY wrap console methods with custom logging utilities for enhanced formatting or filtering while maintaining console as the underlying transport.
- **R-CONSOLE-002** MUST: Core library code MUST use console methods (console.log, console.warn, console.error, console.info, console.debug) for logging without third-party logging framework dependencies.
- **R-CONSOLE-003** SHOULD: Prefer console.error for error conditions, console.warn for warnings, and console.log for informational messages to leverage browser DevTools filtering.
- **R-CONSOLE-004** SHOULD: Use descriptive log messages with sufficient context (function name, relevant variables, operation being performed) to aid debugging.
- **R-CONSOLE-005** SHOULD: Consider using environment checks (e.g., if (process.env.NODE_ENV === 'development')) to conditionally enable verbose logging.
- **R-CONSOLE-006** MUST NOT: Introduce logging framework dependencies (winston, pino, bunyan, log4js) to core library code without architecture team approval and documented exception.
- **R-CONSOLE-007** MUST NOT: Log sensitive data (PII, credentials, tokens) to console without explicit security review.
- **R-CONSOLE-008** SHOULD: Document logging behavior in libraries and provide guidance on how consuming applications can suppress or redirect console output if needed.

### Verify

```bash
# Count console method usage in core libraries
grep -r 'console\.(log|warn|error|info|debug)' packages/core/ --include='*.ts' --include='*.tsx' | wc -l

# Verify no logging framework imports in core libraries
! grep -r 'import.*winston\|import.*pino\|import.*bunyan' packages/core/ --include='*.ts' --include='*.tsx'

# Verify no logging framework dependencies in package.json
npm list --depth=0 | grep -E 'winston|pino|bunyan|log4js' && exit 1 || exit 0
```

**Accept when:**
- Core library code uses console methods for logging without third-party logging dependencies
- No logging frameworks (winston, pino, bunyan, log4js) are listed as dependencies in core package.json
- Console usage is detectable via grep across identified pattern files with consistent usage patterns
- Log statements do not contain obvious sensitive data (PII, credentials, tokens)
- Environment-based log level filtering is implemented for production scenarios

Claude Code MUST verify console-based logging compliance via automated dependency scanning and code review before approving changes to core library logging. Violations require architecture team review and documented exception approval.
</enforcement>
