<rule_activation id="f621c222-7bb3-4b26-8146-118df62ea16a" title="Implement Console Logging with Conditional Debug Output for Development Observability: Development Logging Include" applies_to="**/*">
These rules are ALWAYS ACTIVE for all frontend components, React components, and client-side JavaScript/TypeScript code in development and staging environments.
</rule_activation>

### Rules

- **R-DEVLOG-001** SHOULD: Development logging SHOULD include contextual information such as component names, function names, or operation identifiers to aid in debugging.
- **R-DEVLOG-002** MUST: Use environment variable checks (e.g., `process.env.NODE_ENV !== 'production'`) to conditionally execute logging statements.
- **R-DEVLOG-003** MUST: Never log sensitive data including tokens, passwords, secrets, API keys, or credentials to console.
- **R-DEVLOG-004** MUST: Configure build tools to strip console statements from production builds (e.g., terser with `drop_console: true`).
- **R-DEVLOG-005** SHOULD: Prefix log messages with component or module names for easier filtering (e.g., `console.log('[ComponentName]', message)`).
- **R-DEVLOG-006** SHOULD: Use `console.warn` and `console.error` for important messages instead of `console.log` for all output.
- **R-DEVLOG-007** MAY: Use `console.group/console.groupEnd` for related log messages to improve readability in complex operations.
- **R-DEVLOG-008** MUST: Implement a sanitization utility function that removes or redacts sensitive fields from objects before logging.

### Verify

```bash
# Scan for console statements containing sensitive data patterns
grep -r "console\.log.*token\|console\.log.*password\|console\.log.*secret\|console\.log.*apiKey" --include="*.ts" --include="*.tsx" --include="*.js" --include="*.jsx" .

# Verify production builds have console statements stripped
NODE_ENV=production npm run build && grep -r "console\.log\|console\.warn" dist/ || echo 'No console statements in production build'

# Lint for console usage violations
eslint . --ext .ts,.tsx,.js,.jsx --rule 'no-console: [error, { allow: [warn, error] }]'
```

**Accept when:**
- No console logging statements contain sensitive data patterns (token, password, secret, apiKey, credentials) as verified by grep scan
- Production builds have all `console.log` statements removed or disabled as verified by bundle inspection
- ESLint or similar linting tools are configured to warn or error on `console` usage in production code paths
- All new logging statements are conditional on environment checks and guarded from production builds
- Code review checklist verification confirms logging statements do not expose sensitive information
