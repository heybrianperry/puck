<rule_activation id="1ab25d80-1445-4c22-8705-47f89c475fbc" title="Implement Console Logging with Conditional Debug Output for Development Observability: Any Data Logged" applies_to="**/*">
These rules are ALWAYS ACTIVE for all frontend components, React components, and client-side JavaScript/TypeScript code. Console logging must balance development observability with security and production performance concerns.
</rule_activation>

### Rules

- **R-CONSOLE-001** MUST: Any data logged MUST be sanitized to remove or redact sensitive fields before being passed to console methods.

### Verify

```bash
# Scan for console statements logging sensitive data patterns
grep -r "console\.log.*token\|console\.log.*password\|console\.log.*secret\|console\.log.*apiKey" --include="*.ts" --include="*.tsx" --include="*.js" --include="*.jsx" .

# Verify production builds have console statements stripped
NODE_ENV=production npm run build && grep -r "console\.log\|console\.warn" dist/ || echo 'No console statements in production build'

# Verify ESLint configuration enforces console restrictions
eslint . --ext .ts,.tsx,.js,.jsx --rule 'no-console: [error, { allow: [warn, error] }]' --env-info
```

**Accept when:**
- No console logging statements contain sensitive data patterns (token, password, secret, apiKey, credentials) as verified by grep scan
- Production builds have all console.log statements removed or disabled as verified by bundle inspection
- ESLint or similar linting tools are configured to warn or error on console usage in production code paths
- All logging statements are conditionally guarded by environment checks (e.g., `process.env.NODE_ENV !== 'production'`)
- A sanitization utility function exists and is used to redact sensitive fields before logging
- Log messages are prefixed with component or module names for easier filtering

<enforcement>
Claude Code MUST NOT skip or defer verification. Pre-commit hooks, CI/CD pipeline checks, and code review processes MUST validate compliance with R-CONSOLE-001 before code is merged. Violations block commits and CI builds. Exceptions require security team review and time-bound approval.
</enforcement>
