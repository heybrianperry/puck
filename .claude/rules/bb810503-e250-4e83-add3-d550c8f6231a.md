<rule_activation id="bb810503-e250-4e83-add3-d550c8f6231a" title="Implement Server-Side Request Logging in Remix Entry Points: Sensitive Information Authentication" applies_to="**/entry.server.tsx">
These rules are ALWAYS ACTIVE for all Remix applications with server-side rendering capabilities. They govern logging implementation in entry.server.tsx files to ensure comprehensive observability while protecting sensitive information.
</rule_activation>

### Rules

- **R-REMIX-LOG-001** SHOULD: Sensitive information (authentication tokens, passwords, PII) SHOULD be filtered from logs before emission.

### Verify

```bash
# Check for entry.server.tsx with logging implementation
grep -r 'entry.server.tsx' app/ && grep -E '(console\.log|logger\.|log\()' app/entry.server.tsx

# Verify entry.server.tsx exists and contains request handling
test -f app/entry.server.tsx && grep -E '(handleRequest|handleDataRequest)' app/entry.server.tsx

# Check for logging tests
npm test -- --grep 'entry.server.*logging' || echo 'Add tests for entry.server logging'
```

**Accept when:**
- The entry.server.tsx file contains logging implementation that captures request method, URL, and status code
- Verification commands successfully identify logging statements in entry.server.tsx
- Manual code review confirms that sensitive data is filtered from logs and performance impact is minimal
- Log sanitization middleware or filtering is implemented to prevent PII, credentials, and authentication tokens from being logged
- Structured logging is configured with environment-aware levels (verbose in dev, JSON in production)

<enforcement>
Claude Code MUST verify all conditions in the **Accept when** section before approving entry.server.tsx implementations. Verification is mandatory and MUST NOT be skipped or deferred. Security review of logged data is required to ensure compliance with GDPR, HIPAA, and other data protection regulations.
</enforcement>
