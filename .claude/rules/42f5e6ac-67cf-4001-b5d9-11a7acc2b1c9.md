<rule_activation id="42f5e6ac-67cf-4001-b5d9-11a7acc2b1c9" title="Implement Console Logging with Conditional Debug Output for Development Observability: Console Logging Use" applies_to="**/*">
These rules are ALWAYS ACTIVE for all frontend components, React components, client-side JavaScript and TypeScript code, and development/staging environments.
</rule_activation>

### Rules

- **R-CONSOLE-001** MUST: All console logging MUST use appropriate log levels (console.log for info, console.warn for warnings, console.error for errors) to enable proper filtering and monitoring.
- **R-CONSOLE-002** MUST: Console logging statements MUST be conditional and guarded by environment checks (e.g., process.env.NODE_ENV !== 'production') to prevent exposure in production builds.
- **R-CONSOLE-003** MUST: Console logging MUST NOT contain sensitive data patterns including tokens, passwords, secrets, API keys, credentials, or personally identifiable information (PII).
- **R-CONSOLE-004** MUST: Production builds MUST have all console.log statements automatically stripped or disabled via build tool configuration (terser, babel).
- **R-CONSOLE-005** SHOULD: Log messages SHOULD be prefixed with component or module names for easier filtering (e.g., console.log('[ComponentName]', 'message')).
- **R-CONSOLE-006** SHOULD: Related log messages SHOULD use console.group/console.groupEnd to improve readability in complex operations.
- **R-CONSOLE-007** MAY: Feature flags MAY enable verbose logging for specific users or sessions during production troubleshooting (EXC-002).
- **R-CONSOLE-008** MAY: Critical production errors MAY require immediate console output for emergency debugging (EXC-001), subject to exception process approval.

### Verify

```bash
# Scan for sensitive data patterns in console logging statements
grep -r "console\.log.*token\|console\.log.*password\|console\.log.*secret\|console\.log.*apiKey" --include="*.ts" --include="*.tsx" --include="*.js" --include="*.jsx" .

# Verify production builds have console statements stripped
NODE_ENV=production npm run build && grep -r "console\.log\|console\.warn" dist/ || echo 'No console statements in production build'

# Verify ESLint configuration for console usage
eslint . --ext .ts,.tsx,.js,.jsx --rule 'no-console: [error, { allow: [warn, error] }]' --env-info
```

**Accept when:**
- No console logging statements contain sensitive data patterns (token, password, secret, apiKey, credentials) as verified by grep scan
- Production builds have all console.log statements removed or disabled as verified by bundle inspection
- ESLint or similar linting tools are configured to warn or error on console usage in production code paths
- All console logging statements are guarded by environment variable checks or feature flags
- Build tools (terser, webpack) are configured with 'drop_console: true' for production builds
- Code review checklist verification confirms new logging statements are conditional and contain no sensitive data
