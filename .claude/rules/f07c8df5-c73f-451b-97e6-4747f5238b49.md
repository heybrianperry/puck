<rule_activation id="f07c8df5-c73f-451b-97e6-4747f5238b49" title="Implement Message Queue Logging for State Management Operations: Detailed Payload Contents" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching state management operations that cross component boundaries via message queues, particularly in use-puck.ts and Puck/index.tsx.
</rule_activation>

### Rules

- **R-MQL-001** MAY: Detailed payload contents MAY be logged at debug level for development environments in state management operations crossing component boundaries via message queues.

### Verify

```bash
# Verify message queue logging is present
grep -r "queue.*log\|enqueue.*log\|dequeue.*log" packages/core/lib packages/core/components --include="*.ts" --include="*.tsx"

# Verify correlation IDs are implemented
grep -r "correlationId\|correlation_id" packages/core/lib packages/core/components --include="*.ts" --include="*.tsx"

# Verify logging tests exist
npm test -- --grep "message queue logging" --reporter json | jq '.tests[] | select(.title | contains("logs"))'
```

**Accept when:**
- All message queue enqueue and dequeue operations in use-puck.ts and Puck/index.tsx include structured log statements
- Correlation IDs are present in logs and can be traced through message lifecycle from enqueue to completion
- Unit tests verify that logging occurs for success and failure scenarios in message processing
- Logging is configured at appropriate levels: INFO for enqueue/dequeue, WARN for retries, ERROR for failures, DEBUG for detailed payloads
- Payload sanitization is implemented to prevent logging of sensitive data

### Scope

**In scope:**
- State management operations that cross component boundaries via message queues
- Asynchronous message processing in core state management modules
- UI component interactions that trigger state changes through queued messages
- Message queue integration points in use-puck.ts and Puck component hierarchy

**Out of scope:**
- Synchronous function calls within a single component
- Direct state mutations that do not involve message queues
- Third-party library internal logging
- Browser console logging for development debugging

### Exceptions

- **EXC-001**: High-frequency message operations where logging would degrade performance below acceptable thresholds
- **EXC-002**: Messages containing highly sensitive data where even masked logging poses security risks

Exception process: Submit exception request to architecture team with performance data or security justification; document alternative observability mechanism; obtain approval from relevant stakeholders; add exception documentation to code comments with reference to approval.

<enforcement>
Claude Code MUST verify all message queue operations include structured logging with correlation IDs. Code review MUST block merge if logging requirements are not met. CI pipeline MUST fail if static analysis detects unlogged queue operations. Post-deployment monitoring MUST alert if expected log patterns are missing from production logs.
</enforcement>
