<rule_activation id="8c23d689-8baf-43a3-b6d9-bb2f6a9d044c" title="Adopt Modular Library Architecture with Core Package Pattern: Application Specific Logic" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the codebase to enforce modular library architecture with clear separation between core packages and application-specific logic.
</rule_activation>

### Rules

- **R-CORE-001** MUST NOT: Application-specific logic MUST NOT be placed in the core package; it should remain in application directories (e.g., recipes/)
- **R-CORE-002** MUST: All reusable utility functions and data transformation logic belong in packages/core/lib
- **R-CORE-003** MUST: All reusable UI components intended for use across multiple features or applications belong in packages/core/components
- **R-CORE-004** MUST: Custom React hooks that encapsulate reusable stateful logic belong in packages/core/lib
- **R-CORE-005** MUST: Build and bundling configuration for library packages be maintained in centralized locations (e.g., packages/tsup-config/)
- **R-CORE-006** MUST: Server-side rendering implementations of core components have corresponding server.tsx files
- **R-CORE-007** MUST NOT: Core packages import from application-specific directories (e.g., recipes/)
- **R-CORE-008** SHOULD: Components be used in at least 2-3 places before promotion to core package
- **R-CORE-009** SHOULD: Maintain semantic versioning with clear deprecation policies for core packages
- **R-CORE-010** MAY: Prototype components in application directories before promotion to core (EXC-001)
- **R-CORE-011** MAY: Keep utility functions with application-specific dependencies outside core if abstraction is not feasible (EXC-002)

### Verify

```bash
# Count utility files in core/lib
find packages/core/lib -type f \( -name '*.ts' -o -name '*.tsx' \) | wc -l

# Count component index files in core/components
find packages/core/components -type f -name 'index.tsx' | wc -l

# Verify no application imports in core packages
grep -r 'from.*recipes/' packages/core/ && echo 'ERROR: Core package imports from application code' || echo 'OK: No application imports in core'

# Verify build config exists
test -f packages/tsup-config/react-import.js && echo 'OK: Build config exists' || echo 'ERROR: Missing build config'

# Detect circular dependencies
dependency-cruiser --validate .dependency-cruiser.js packages/core/ || echo 'WARNING: Circular dependencies detected'
```

**Accept when:**
- Core package contains multiple utility modules in lib directory and multiple components in components directory
- No imports from application-specific directories (e.g., recipes/) are found in core package files
- Build configuration for library packages exists in a centralized location
- Components that require server-side rendering have corresponding server.tsx implementations
- No circular dependencies exist between core packages and application code
- All reusable code follows established naming conventions (packages/core/lib for utilities, packages/core/components for UI)

<enforcement>
Claude Code MUST verify all rules before accepting code changes. Violations of R-CORE-001 and R-CORE-007 are blocking. Code review and CI pipeline checks are mandatory. Exceptions require tech lead approval and documentation.
</enforcement>
