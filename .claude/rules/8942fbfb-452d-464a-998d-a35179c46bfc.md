<rule_activation id="8942fbfb-452d-464a-998d-a35179c46bfc" title="Adopt Modular Library Architecture with Core Package Pattern: Reusable Components Organized" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the codebase to enforce modular library architecture with clear separation between core packages and application-specific code.
</rule_activation>

### Rules

- **R-MOD-001** MUST: Reusable UI components MUST be organized in packages/core/components with index.tsx as the primary export file
- **R-MOD-002** MUST: All reusable utility functions and data transformation logic MUST be placed in packages/core/lib
- **R-MOD-003** MUST: Custom React hooks that encapsulate reusable stateful logic MUST be organized in packages/core/lib
- **R-MOD-004** MUST: Core packages MUST NOT import from application-specific directories (e.g., recipes/)
- **R-MOD-005** MUST: One-way dependency flow MUST be enforced: applications depend on core, never vice versa
- **R-MOD-006** SHOULD: Components should be used in at least 2-3 places before promotion to core packages
- **R-MOD-007** SHOULD: Server-side rendering implementations of core components SHOULD have corresponding server.tsx files
- **R-MOD-008** MAY: Components may be prototyped in application directories before promotion to core (EXC-001)
- **R-MOD-009** MAY: Utility functions with application-specific dependencies may remain in application code if abstraction is not feasible (EXC-002)

### Verify

```bash
# Count utility files in core/lib
find packages/core/lib -type f \( -name '*.ts' -o -name '*.tsx' \) | wc -l

# Count component index files in core/components
find packages/core/components -type f -name 'index.tsx' | wc -l

# Check for circular dependencies: core importing from application code
grep -r 'from.*recipes/' packages/core/ && echo 'ERROR: Core package imports from application code' || echo 'OK: No application imports in core'

# Verify build configuration exists
test -f packages/tsup-config/react-import.js && echo 'OK: Build config exists' || echo 'ERROR: Missing build config'

# Check for server-side rendering implementations
find packages/core/components -type f -name 'server.tsx' | wc -l
```

**Accept when:**
- Core package contains multiple utility modules in lib directory and multiple components in components directory
- No imports from application-specific directories (e.g., recipes/) are found in core package files
- Build configuration for library packages exists in a centralized location (packages/tsup-config/)
- Components that require server-side rendering have corresponding server.tsx implementations
- All reusable UI components have index.tsx as the primary export file
- Dependency analysis tools confirm no circular dependencies between core and application code
