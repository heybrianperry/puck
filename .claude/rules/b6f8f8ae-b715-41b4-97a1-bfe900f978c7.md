<rule_activation id="b6f8f8ae-b715-41b4-97a1-bfe900f978c7" title="Implement Console Logging with Conditional Debug Output for Development Observability: Logging Statements Not" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. Console logging must provide development observability while preventing exposure of sensitive information and maintaining production performance.
</rule_activation>

### Rules

- **R-CONSOLE-001** MUST_NOT: Logging statements MUST NOT include sensitive information such as authentication tokens, API keys, passwords, personal identifiable information (PII), or any data marked as confidential.
- **R-CONSOLE-002** MUST: Use environment variable checks (e.g., `process.env.NODE_ENV !== 'production'`) to conditionally execute logging statements.
- **R-CONSOLE-003** MUST: Configure build tools to strip console statements from production builds (e.g., terser with `drop_console: true`).
- **R-CONSOLE-004** SHOULD: Create and use a sanitization utility function that removes or redacts sensitive fields from objects before logging.
- **R-CONSOLE-005** SHOULD: Prefix log messages with component or module names for easier filtering (e.g., `console.log('[ComponentName]', message)`).
- **R-CONSOLE-006** SHOULD: Use `console.warn` and `console.error` for important messages rather than `console.log` for all output.
- **R-CONSOLE-007** MAY: Use `console.group/console.groupEnd` for related log messages to improve readability in complex operations.

### Verify

```bash
# Scan for console statements containing sensitive data patterns
grep -r "console\.log.*token\|console\.log.*password\|console\.log.*secret\|console\.log.*apiKey" --include="*.ts" --include="*.tsx" --include="*.js" --include="*.jsx" .

# Verify production builds have console statements stripped
NODE_ENV=production npm run build && grep -r "console\.log\|console\.warn" dist/ || echo 'No console statements in production build'

# Lint for console usage violations
eslint . --ext .ts,.tsx,.js,.jsx --rule 'no-console: [error, { allow: [warn, error] }]'
```

**Accept when:**
- No console logging statements contain sensitive data patterns (token, password, secret, apiKey, credentials) as verified by grep scan
- Production builds have all `console.log` statements removed or disabled as verified by bundle inspection
- ESLint or similar linting tools are configured to warn or error on `console` usage in production code paths
- All new logging statements are conditional on environment checks and guarded from production execution
- Code review checklist verification confirms logging statements do not expose sensitive data
