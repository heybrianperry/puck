<rule_activation id="d0c4472f-8f2f-4b0d-805f-0b54a80562f4" title="Adopt Catch-All Route Patterns for Dynamic Content Management Systems: Cms Integration Routes" applies_to="**/*">
These rules are ACTIVE for all public-facing API routes and dynamic content management integrations in Next.js, Remix, and React Router applications.
</rule_activation>

### Rules

- **R-CMS-001** MUST: CMS integration routes MUST be placed at the appropriate nesting level to capture all intended content paths (e.g., /puck/[...puckPath] or /api/puck/$)
- **R-CMS-002** MUST: Use framework-specific parameter extraction: params.puckPath (Next.js), params.$ (Remix), or params['*'] (React Router) to access the full captured path
- **R-CMS-003** MUST: Implement consistent error handling for unresolved paths, returning appropriate 404 responses rather than exposing internal errors
- **R-CMS-004** SHOULD: Implement path normalization (trailing slashes, case sensitivity) before passing to CMS resolution layer to ensure consistent behavior
- **R-CMS-005** SHOULD: Add monitoring and logging for catch-all route performance to identify slow CMS resolution patterns and optimize accordingly
- **R-CMS-006** MUST: Implement strict path validation, sanitization, and authorization checks before CMS resolution
- **R-CMS-007** SHOULD: Implement caching layer and fallback mechanisms for CMS connectivity

### Verify

```bash
# Verify catch-all route patterns in Next.js
grep -r "\[\.\.\..*\]" --include="page.tsx" --include="route.tsx" app/

# Verify catch-all route patterns in Remix
grep -r "params\.\$" --include="*.tsx" app/routes/

# Verify catch-all route patterns in React Router
grep -r "splat" --include="*.tsx" app/routes/

# Find catch-all route files by naming convention
find . -type f \( -name "*[...]*" -o -name "*\$*" -o -name "*splat*" \) -path "*/routes/*" -o -path "*/app/*"

# Verify CMS path parameters are properly extracted
grep -r "puckPath\|cmsPath" --include="*.tsx" --include="*.ts" app/ | grep -E "params\.(puckPath|\$|\*)"
```

**Accept when:**
- All CMS integration routes use framework-native catch-all syntax and can be identified by grep patterns
- Route handlers extract and pass full paths to CMS resolution without modification or truncation
- No custom routing middleware is implemented for CMS path resolution in new code
- All catch-all routes include proper error handling for unresolved paths with appropriate HTTP status codes
- Path validation and authorization checks are implemented before CMS resolution
- Caching and fallback mechanisms are in place for CMS connectivity
