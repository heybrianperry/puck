These rules are ALWAYS ACTIVE for all files in the codebase to enforce modular library architecture with clear separation between core packages and application-specific code.
</rule_activation>

### Rules

- **R-MODULAR-001** MUST: Components that support server-side rendering MUST provide separate server.tsx implementations alongside client components.
- **R-MODULAR-002** MUST: Core packages MUST NOT import from application-specific directories (e.g., recipes/).
- **R-MODULAR-003** MUST: Reusable utility functions and data transformation logic MUST be placed in packages/core/lib.
- **R-MODULAR-004** MUST: Reusable UI components intended for use across multiple features or applications MUST be placed in packages/core/components.
- **R-MODULAR-005** MUST: Custom React hooks that encapsulate reusable stateful logic MUST be placed in packages/core/lib.
- **R-MODULAR-006** SHOULD: Components SHOULD only be promoted to core packages after being used in at least 2-3 places.
- **R-MODULAR-007** SHOULD: Circular dependencies between core packages and application code SHOULD be prevented through linting rules and one-way dependency flow enforcement.

### Verify

```bash
# Count utility files in core/lib
find packages/core/lib -type f \( -name '*.ts' -o -name '*.tsx' \) | wc -l

# Count component index files in core/components
find packages/core/components -type f -name 'index.tsx' | wc -l

# Verify no application imports in core packages
grep -r 'from.*recipes/' packages/core/ && echo 'ERROR: Core package imports from application code' || echo 'OK: No application imports in core'

# Verify build config exists
test -f packages/tsup-config/react-import.js && echo 'OK: Build config exists' || echo 'ERROR: Missing build config'

# Verify server.tsx implementations exist for SSR components
find packages/core/components -type f -name 'server.tsx' | wc -l
```

**Accept when:**
- Core package contains multiple utility modules in lib directory and multiple components in components directory
- No imports from application-specific directories (e.g., recipes/) are found in core package files
- Build configuration for library packages exists in a centralized location
- Components that require server-side rendering have corresponding server.tsx implementations
- Dependency analysis tools detect no circular dependencies between core and application code
- Core packages can be built and tested independently
