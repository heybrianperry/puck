<rule_activation id="667cbd91-66c4-4281-8cad-f86e4ce3c0d6" title="Adopt Async Data Resolution with Concurrent Promise Handling for Logging Operations: Resolution Operations Avoid" applies_to="packages/core/lib/data/**/*.ts">
These rules are ALWAYS ACTIVE for all data resolution operations within the logging subsystem.
</rule_activation>

### Rules

- **R-ASYNC-001** SHOULD: Resolution operations SHOULD avoid blocking the event loop by delegating I/O-bound operations to async functions.

### Verify

```bash
# Count async resolution functions
grep -r 'async.*function.*resolve' packages/core/lib/data/ | wc -l

# Count concurrent Promise patterns
grep -r 'Promise\.all\|Promise\.allSettled' packages/core/lib/data/ | wc -l

# Count await statements in resolution code
grep -r 'await.*resolve' packages/core/lib/data/ | wc -l
```

**Accept when:**
- All data resolution functions in `packages/core/lib/data/` are declared as `async` or return `Promise` types
- At least one instance of `Promise.all()` or `Promise.allSettled()` is used for concurrent operations
- All `await` statements are wrapped in appropriate error handling (`try/catch` or `.catch()`)
- ESLint rules for Promise handling (`no-floating-promises`, `require-await`) pass without violations
- Unit tests verify concurrent behavior and error handling of data resolution functions

<enforcement>
Claude Code MUST verify all rules in this activation block. Violations of R-ASYNC-001 require explicit justification in code comments and tech lead approval. CI pipeline enforcement includes ESLint checks and mandatory error handling tests.
</enforcement>
