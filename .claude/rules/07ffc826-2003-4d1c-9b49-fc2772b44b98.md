<rule_activation id="07ffc826-2003-4d1c-9b49-fc2772b44b98" title="Adopt Modular Library Architecture with Core Package Pattern: Custom React Hooks" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the codebase to enforce modular library architecture with clear separation between core packages and application-specific code.
</rule_activation>

### Rules

- **R-CORE-001** SHOULD: Custom React hooks SHOULD follow the use-* naming convention and be placed in packages/core/lib
- **R-CORE-002** SHOULD: All reusable utility functions and data transformation logic SHOULD be placed in packages/core/lib
- **R-CORE-003** SHOULD: All reusable UI components intended for use across multiple features or applications SHOULD be placed in packages/core/components
- **R-CORE-004** MUST: Core packages MUST NOT import from application-specific directories (e.g., recipes/)
- **R-CORE-005** MUST: One-way dependency flow MUST be enforced: applications depend on core, never vice versa
- **R-CORE-006** SHOULD: Server-side rendering implementations of core components SHOULD have corresponding server.tsx implementations
- **R-CORE-007** MAY: Application-specific business logic and feature implementations MAY remain in application directories
- **R-CORE-008** MAY: One-off components used in a single feature without reuse potential MAY remain in application directories

### Verify

```bash
# Count utility files in core/lib
find packages/core/lib -type f \( -name '*.ts' -o -name '*.tsx' \) | wc -l

# Count component index files in core/components
find packages/core/components -type f -name 'index.tsx' | wc -l

# Verify no application imports in core packages
grep -r 'from.*recipes/' packages/core/ && echo 'ERROR: Core package imports from application code' || echo 'OK: No application imports in core'

# Verify build config exists
test -f packages/tsup-config/react-import.js && echo 'OK: Build config exists' || echo 'ERROR: Missing build config'

# Verify no circular dependencies
dependency-cruiser --validate .dependency-cruiser.js packages/core/ || echo 'WARNING: Circular dependencies detected'
```

**Accept when:**
- Core package contains multiple utility modules in lib directory and multiple components in components directory
- No imports from application-specific directories (e.g., recipes/) are found in core package files
- Build configuration for library packages exists in a centralized location
- Components that require server-side rendering have corresponding server.tsx implementations
- Custom React hooks follow the use-* naming convention
- All reusable utilities and components are properly organized in their respective directories

<enforcement>
Claude Code MUST verify all R-CORE rules before approving code placement decisions. Violations of R-CORE-004 and R-CORE-005 (MUST rules) MUST block approval. Violations of SHOULD rules SHOULD be flagged for review and remediation. Circular dependency detection MUST run in CI and MUST fail the build if violations are found.
</enforcement>
