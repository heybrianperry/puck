<rule_activation id="96aa61bb-eb31-4546-9ed4-9f7369dbe4f4" title="Adopt TypeScript Configuration Export Pattern for Public API Packages: Public Packages Use" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching public packages under /packages/*, API route handlers, and shared configuration packages.
</rule_activation>

### Rules

- **R-TSCONFIG-001** SHOULD: Public packages SHOULD use shared build configuration (e.g., tsup-config package) to maintain consistency across the monorepo.
- **R-TSCONFIG-002** SHOULD: Define package.json exports field with explicit entry points for main, types, and any conditional exports (import/require).
- **R-TSCONFIG-003** SHOULD: Include both ESM and CJS outputs when necessary for broader compatibility, but prefer ESM as the primary format.
- **R-TSCONFIG-004** SHOULD: Document public API surface in README files and consider using API Extractor or similar tools to generate API documentation.
- **R-TSCONFIG-005** SHOULD: For API route handlers, follow the established naming pattern (api.*.tsx) to make external interfaces immediately recognizable.
- **R-TSCONFIG-006** SHOULD: Leverage TypeScript's declaration maps for better debugging experience in consumer projects.

### Verify

```bash
# Count tsup.config.ts files in packages
grep -r "tsup.config.ts" packages/*/tsup.config.ts | wc -l

# Count package.json files with exports field
find packages -name 'package.json' -exec jq -e '.exports' {} \; 2>/dev/null | wc -l

# Count explicit exports from index.ts files
grep -r "export.*from" packages/*/index.ts | grep -v "// internal" | wc -l
```

**Accept when:**
- All public packages under /packages/* contain either tsup.config.ts or equivalent build configuration
- Package.json files for public packages define explicit exports field with type definitions
- API route handlers follow consistent naming conventions (api.* or routes/api/*) across recipe applications
- Shared build configuration (tsup-config) is used by at least 80% of public packages

<enforcement>
Claude Code MUST verify all acceptance criteria before approving changes to public packages, API route handlers, or build configurations. Verification is mandatory and MUST NOT be skipped or deferred.
</enforcement>
