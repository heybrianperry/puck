<rule_activation id="7c95d998-0d17-44c0-b794-929da06801f5" title="Implement Server-Side Request Logging in Remix Entry Points: Request Logs Include" applies_to="**/entry.server.tsx">
These rules are ALWAYS ACTIVE for all Remix applications with server-side rendering capabilities. They govern logging implementation in entry.server.tsx files.
</rule_activation>

### Rules

- **R-REMIX-LOG-001** MUST: Request logs MUST include at minimum: HTTP method, URL path, timestamp, and response status code

### Verify

```bash
# Check for entry.server.tsx file and logging statements
grep -r 'entry.server.tsx' app/ && grep -E '(console\.log|logger\.|log\()' app/entry.server.tsx

# Verify entry.server.tsx exists and contains request handling
test -f app/entry.server.tsx && grep -E '(handleRequest|handleDataRequest)' app/entry.server.tsx

# Check for logging tests
npm test -- --grep 'entry.server.*logging' || echo 'Add tests for entry.server logging'
```

**Accept when:**
- The entry.server.tsx file contains logging implementation that captures request method, URL, and status code
- Verification commands successfully identify logging statements in entry.server.tsx
- Manual code review confirms that sensitive data is filtered from logs and performance impact is minimal
- Logs are structured and include timestamp information
- No sensitive user data (PII, credentials) is logged

<enforcement>
Claude Code MUST NOT skip or defer verification of logging implementation in entry.server.tsx. All R-REMIX-LOG-### rules are mandatory for Remix applications with server-side rendering.
</enforcement>
