<rule_activation id="e71b21de-0ed5-4807-b09d-46c9f96dc666" title="Adopt Browser-Based Rendering Model for E2E Testing Infrastructure: Utility Functions Measuring" applies_to="**/*">
These rules are ALWAYS ACTIVE for E2E testing infrastructure, utility functions, and test setup modules that interact with browser rendering engines.
</rule_activation>

### Rules

- **R-E2E-001** SHOULD: Utility functions for measuring UI elements SHOULD be centralized in dedicated modules (e.g., get-box.mjs) to ensure consistency across E2E test suites.

### Verify

```bash
# Check for browser-native rendering APIs in E2E utility modules
grep -r 'getBoundingClientRect\|getComputedStyle' scripts/e2e/utils/ --include='*.mjs' --include='*.js'

# Verify required utility modules exist
test -f scripts/e2e/utils/setup.mjs && test -f scripts/e2e/utils/get-box.mjs

# Run E2E test suite and verify tests pass
npm test -- --grep 'e2e' 2>&1 | grep -q 'passed' || echo 'E2E tests not found or failing'
```

**Accept when:**
- E2E utility modules exist in scripts/e2e/utils/ and use browser-native rendering APIs (getBoundingClientRect, getComputedStyle, etc.)
- Test setup modules initialize browser contexts with consistent configurations before running tests
- E2E test suite passes successfully with rendering-based validations for UI element properties
- Utility functions are centralized in dedicated modules rather than inlined in individual test files
- Public API contracts for utility functions are documented and consistent across test suites

<enforcement>
Claude Code MUST verify that E2E testing infrastructure follows the browser-based rendering model. Verification is mandatory before accepting changes to E2E test utilities, setup modules, or rendering-related helper functions. Violations must be flagged in code review and CI pipeline checks must pass.
</enforcement>
