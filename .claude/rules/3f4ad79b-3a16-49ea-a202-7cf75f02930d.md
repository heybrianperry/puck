### Rules

- **R-ASYNC-001** MUST: All data resolution operations in the logging subsystem MUST use async/await pattern for asynchronous data retrieval
- **R-ASYNC-002** MUST: Use TypeScript's strict null checking to ensure all Promise return types are properly typed
- **R-ASYNC-003** MUST: Implement consistent timeout values for all data resolution operations to prevent hanging Promises
- **R-ASYNC-004** SHOULD: Use Promise.allSettled() instead of Promise.all() when you need to collect results even if some operations fail
- **R-ASYNC-005** MUST: Add comprehensive logging for Promise rejections to aid in debugging async operation failures
- **R-ASYNC-006** MUST: All await statements MUST be wrapped in appropriate error handling (try/catch or .catch())
- **R-ASYNC-007** SHOULD: Implement rate limiting or batching mechanisms for high-volume concurrent operations; consider using Promise pooling libraries
- **R-ASYNC-008** MUST: Implement timeout mechanisms for all async operations and ensure proper cleanup of Promise chains

**Accept when:**
- All data resolution functions in packages/core/lib/data/ are declared as async or return Promises

- All await statements are wrapped in appropriate error handling (try/catch or .catch())
- ESLint rules for Promise handling (no-floating-promises, require-await) pass without violations
- Unit tests verify concurrent behavior and error handling of data resolution functions
