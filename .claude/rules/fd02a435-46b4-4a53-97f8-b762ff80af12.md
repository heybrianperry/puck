<rule_activation id="fd02a435-46b4-4a53-97f8-b762ff80af12" title="Standardize Logging and Observability Configuration in Runtime Environments: Logging Configuration Externalized" applies_to="**/*">
These rules are ALWAYS ACTIVE for all TypeScript/JavaScript runtime components (libraries, servers, CLI tools), environment variable configuration, and observability infrastructure.
</rule_activation>

### Rules

- **R-LOG-001** MUST: Logging configuration MUST be externalized through environment variables or configuration files rather than hardcoded in application logic.

### Verify

```bash
# Count direct console usage in TypeScript/JavaScript files
grep -r 'console\.(log|error|warn)' --include='*.ts' --include='*.js' packages/ recipes/ | wc -l

# Verify environment-based logging configuration usage
grep -r 'process\.env\.LOG_LEVEL\|process\.env\.NODE_ENV' --include='*.ts' --include='*.js' packages/ recipes/ | wc -l

# Check ESLint enforcement of no-console rule
npm run lint -- --rule 'no-console: error' 2>&1 | grep -c 'no-console'
```

**Accept when:**
- All components in packages/ and recipes/ directories use environment-based logging configuration rather than hardcoded console statements
- Grep for environment variable usage (LOG_LEVEL, NODE_ENV) returns matches in at least 80% of runtime components
- Linting rules enforce structured logging patterns and flag direct console usage in production code paths

<enforcement>
Claude Code MUST NOT skip or defer verification. Logging configuration compliance is verified by automated CI pipeline checks using ESLint rules, code review checklists, and periodic architecture audits. Violations block CI pipelines and merge requests.
</enforcement>
