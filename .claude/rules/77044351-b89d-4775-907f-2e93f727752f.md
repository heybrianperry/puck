<rule_activation id="77044351-b89d-4775-907f-2e93f727752f" title="Implement Cache Layer for Configuration and Environment Data: Applications Implement Tiered" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime environments and configuration management systems. All components that handle configuration data or environment variables MUST comply with the caching requirements specified herein.
</rule_activation>

### Rules

- **R-CACHE-001** MAY: Applications MAY implement tiered caching strategies with different TTLs for different configuration categories.
- **R-CACHE-002** MUST: Configuration values must be read directly from environment without caching for security-critical operations like authentication token validation (EXC-001).
- **R-CACHE-003** MAY: Development and testing environments may disable caching to facilitate rapid configuration changes (EXC-002).
- **R-CACHE-004** SHOULD: Use a singleton pattern or module-level cache to ensure configuration is cached once per application instance.
- **R-CACHE-005** SHOULD: Implement cache warming during application startup to avoid cold start penalties on first requests.
- **R-CACHE-006** SHOULD: Consider using a Map or WeakMap for cache storage to enable efficient lookups and automatic garbage collection.
- **R-CACHE-007** SHOULD: Add instrumentation to track cache hit rates, miss rates, and access patterns for performance monitoring.
- **R-CACHE-008** SHOULD: Implement cache invalidation hooks triggered by configuration file changes or environment variable updates.
- **R-CACHE-009** SHOULD: Implement strict filtering to prevent caching of sensitive data patterns and use encryption for any cached sensitive values.
- **R-CACHE-010** SHOULD: Implement cache size limits and eviction policies with monitoring and alerts for cache memory usage.

### Verify

```bash
# Check for cache and config patterns in TypeScript/JavaScript files
grep -r 'cache.*config\|config.*cache' --include='*.ts' --include='*.tsx' --include='*.js' --include='*.jsx' .

# Check for cached environment variable access patterns
grep -r 'process\.env' --include='*.ts' --include='*.tsx' | grep -c 'cache\|memo' || echo 'No cached env access found'

# Run cache configuration tests
npm test -- --grep 'cache.*configuration|configuration.*cache'
```

**Accept when:**
- Configuration access code demonstrates caching mechanism with evidence of in-memory storage
- Cache invalidation or refresh logic is present and tested
- No direct process.env access in hot paths without caching layer
- Performance tests show reduced configuration access latency compared to uncached baseline
- Sensitive data filtering is implemented to prevent caching of credentials or secrets
- Cache size limits and eviction policies are documented and enforced

<enforcement>
Claude Code MUST verify cache layer implementation during code review. Violations in hot paths MUST be flagged. Performance regression checks MUST run in CI pipeline. Manual review of sensitive data handling is mandatory before approval.
</enforcement>
