<rule_activation id="5aedd035-1b66-405e-ba00-01d7f508250f" title="Adopt Event-Driven Synchronization for State Management in Integration Boundaries: Synchronization Logic Isolated" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching integration boundaries, state management components, and external system coordination logic.
</rule_activation>

### Rules

- **R-EVDS-001** SHOULD: Synchronization logic SHOULD be isolated from business logic to enable independent testing and maintenance.

### Verify

```bash
# Identify event-driven synchronization patterns with hooks or event listeners
grep -r "use.*[Ss]ync" --include="*.ts" --include="*.tsx" --include="*.js" | grep -E "(hook|event|subscribe)"

# Count event listeners and subscriptions across codebase
grep -r "addEventListener\|on(.*\)\|subscribe" --include="*.ts" --include="*.tsx" --include="*.js" | wc -l

# Find files implementing event-driven synchronization patterns
find . -type f \( -name "*.ts" -o -name "*.tsx" -o -name "*.js" \) -exec grep -l "event.*sync\|sync.*event" {} \;
```

**Accept when:**
- Grep commands identify at least 2 files implementing event-driven synchronization patterns with hooks or event listeners
- Code review confirms that integration boundaries use event-driven patterns rather than direct synchronous coupling
- No new direct synchronous state coupling is introduced at integration boundaries without architectural review approval

<enforcement>
Claude Code MUST verify event-driven synchronization patterns are properly isolated from business logic. Verification is mandatory before accepting changes to integration boundaries or state management components. Architecture review is required for any new integration points or exceptions to this pattern.
</enforcement>
