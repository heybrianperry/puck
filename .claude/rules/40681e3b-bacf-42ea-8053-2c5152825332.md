<rule_activation id="40681e3b-bacf-42ea-8053-2c5152825332" title="Adopt TypeScript Configuration Export Pattern for Public API Packages: Public Facing Packages" applies_to="**/*">
These rules are ALWAYS ACTIVE for all public-facing packages under /packages/* and API route handlers in recipe/example applications.
</rule_activation>

### Rules

- **R-TSCONFIG-001** MUST: All public-facing packages MUST define their exports through explicit configuration files (tsup.config.ts, package.json exports field, or equivalent).
- **R-TSCONFIG-002** MUST: Use the shared tsup-config package as the foundation for all new public packages to ensure consistency.
- **R-TSCONFIG-003** MUST: Define package.json exports field with explicit entry points for main, types, and any conditional exports (import/require).
- **R-TSCONFIG-004** SHOULD: Include both ESM and CJS outputs when necessary for broader compatibility, but prefer ESM as the primary format.
- **R-TSCONFIG-005** SHOULD: Document public API surface in README files and consider using API Extractor or similar tools to generate API documentation.
- **R-TSCONFIG-006** SHOULD: For API route handlers, follow the established naming pattern (api.*.tsx) to make external interfaces immediately recognizable.
- **R-TSCONFIG-007** SHOULD: Leverage TypeScript's declaration maps for better debugging experience in consumer projects.

### Verify

```bash
# Count tsup.config.ts files in packages
grep -r "tsup.config.ts" packages/*/tsup.config.ts | wc -l

# Count package.json files with exports field
find packages -name 'package.json' -exec jq -e '.exports' {} \; 2>/dev/null | wc -l

# Count explicit exports from index.ts files
grep -r "export.*from" packages/*/index.ts | grep -v "// internal" | wc -l
```

**Accept when:**
- All public packages under /packages/* contain either tsup.config.ts or equivalent build configuration
- Package.json files for public packages define explicit exports field with type definitions
- API route handlers follow consistent naming conventions (api.* or routes/api/*) across recipe applications
- Shared build configuration (tsup-config) is used by at least 80% of public packages

<enforcement>
Claude Code MUST verify all rules using the provided bash commands before accepting new packages or modifications to public-facing exports. Violations trigger CI pipeline failures and require remediation or documented exceptions with architecture review approval.
</enforcement>
