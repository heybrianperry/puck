<rule_activation id="90feb6fc-aa2e-4584-a7a0-f5071161e82f" title="Adopt TypeScript Configuration Export Pattern for Public API Packages: Public Modules Export" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in packages intended for external consumption, API route handlers, shared configuration packages, plugin packages, and field adapter packages.
</rule_activation>

### Rules

- **R-TSC-001** MUST: Public API modules MUST export TypeScript type definitions alongside runtime code to ensure type safety for consumers.
- **R-TSC-002** MUST: All public packages under /packages/* MUST contain either tsup.config.ts or equivalent build configuration.
- **R-TSC-003** MUST: Package.json files for public packages MUST define explicit exports field with type definitions.
- **R-TSC-004** MUST: API route handlers MUST follow consistent naming conventions (api.* or routes/api/*) across recipe applications.
- **R-TSC-005** SHOULD: Use the shared tsup-config package as the foundation for all new public packages to ensure consistency.
- **R-TSC-006** SHOULD: Define package.json exports field with explicit entry points for main, types, and any conditional exports (import/require).
- **R-TSC-007** SHOULD: Include both ESM and CJS outputs when necessary for broader compatibility, but prefer ESM as the primary format.
- **R-TSC-008** SHOULD: Document public API surface in README files and consider using API Extractor or similar tools to generate API documentation.
- **R-TSC-009** SHOULD: Leverage TypeScript's declaration maps for better debugging experience in consumer projects.
- **R-TSC-010** MAY: Use runtime API registration to complement rather than replace static exports for core APIs in plugin systems requiring dynamic loading.

### Verify

```bash
# Count tsup.config.ts files in packages
grep -r "tsup.config.ts" packages/*/tsup.config.ts | wc -l

# Count package.json files with exports field
find packages -name 'package.json' -exec jq -e '.exports' {} \; 2>/dev/null | wc -l

# Count explicit exports in index.ts files
grep -r "export.*from" packages/*/index.ts | grep -v "// internal" | wc -l
```

**Accept when:**
- All public packages under /packages/* contain either tsup.config.ts or equivalent build configuration
- Package.json files for public packages define explicit exports field with type definitions
- API route handlers follow consistent naming conventions (api.* or routes/api/*) across recipe applications
- Shared build configuration (tsup-config) is used by at least 80% of public packages
- Automated CI checks using publint or package-lint verify export configurations
- TypeScript compilation checks ensure type definitions are properly generated and exported
- Automated tests confirm expected exports are available when importing packages
