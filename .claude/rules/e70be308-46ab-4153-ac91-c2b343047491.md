<rule_activation id="e70be308-46ab-4153-ac91-c2b343047491" title="Adopt TypeScript Configuration Export Pattern for Public API Packages: Internal Implementation Details" applies_to="**/*">
These rules are ALWAYS ACTIVE for all packages under /packages/* intended for external consumption, API route handlers in recipe/example applications, shared configuration packages, plugin packages, and field adapter packages.
</rule_activation>

### Rules

- **R-EXPORT-001** MUST_NOT: Internal implementation details MUST NOT be exposed through public package exports unless explicitly marked as unstable or internal

### Verify

```bash
# Verify tsup.config.ts exists in public packages
grep -r "tsup.config.ts" packages/*/tsup.config.ts | wc -l

# Verify package.json exports field is defined
find packages -name 'package.json' -exec jq -e '.exports' {} \; 2>/dev/null | wc -l

# Verify explicit exports in index.ts files
grep -r "export.*from" packages/*/index.ts | grep -v "// internal" | wc -l
```

**Accept when:**
- All public packages under /packages/* contain either tsup.config.ts or equivalent build configuration
- Package.json files for public packages define explicit exports field with type definitions
- API route handlers follow consistent naming conventions (api.* or routes/api/*) across recipe applications
- Shared build configuration (tsup-config) is used by at least 80% of public packages

<enforcement>
Claude Code MUST verify all rules through automated CI checks using publint or package-lint. Code review checklists MUST require verification of tsup.config.ts and package.json exports for new packages. Automated tests MUST import packages and verify expected exports are available. TypeScript compilation checks MUST ensure type definitions are properly generated and exported. Violations trigger CI pipeline failures. Pull requests adding new packages MUST include build configuration or written justification for exemption. Quarterly audits MUST identify non-compliant packages. Breaking changes to exports MUST trigger major version bumps per semantic versioning. Exceptions require written justification and architecture review approval, with all exceptions documented in a central registry.
</enforcement>
