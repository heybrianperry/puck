<rule_activation id="3915e091-41e3-4f0f-949c-dc2b4fb561d9" title="Standardize Runtime Configuration Loading with Concurrent Environment Resolution: Environment Variable Resolution" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime configuration and environment management implementations across the codebase, including API route handlers, server-side modules, client-side components, and configuration initialization code in Next.js, React Router, and similar frameworks.
</rule_activation>

### Rules

- **R-CONFIG-001** MUST: Environment variable resolution MUST be thread-safe and support concurrent reads during application initialization and runtime execution.

### Verify

```bash
# Count environment variable access patterns
grep -r 'process\.env' --include='*.ts' --include='*.tsx' | grep -v 'node_modules' | wc -l

# Find configuration loading and environment resolution code
find . -name '*.ts' -o -name '*.tsx' | xargs grep -l 'config.*load\|environment.*resolve' | grep -v node_modules

# Run configuration and environment tests with coverage
npm test -- --testPathPattern='config|environment' --coverage
```

**Accept when:**
- All configuration loading code follows the standardized pattern with documented concurrent access semantics
- Integration tests demonstrate thread-safe behavior under concurrent access from multiple execution contexts
- Code review checklist includes verification of configuration pattern compliance for new API routes and server modules
- Performance benchmarks show no significant regression in configuration loading latency compared to baseline
- Static analysis rules detect direct environment variable access outside approved configuration modules
- Configuration loading is implemented with lazy initialization using thread-safe singleton pattern or equivalent concurrency primitive
- Memoization or caching is used for resolved configuration values to minimize redundant environment variable lookups

<enforcement>
Claude Code MUST NOT skip or defer verification. All configuration loading implementations MUST comply with R-CONFIG-001. Violations trigger CI pipeline failure, code review blocks, and automated issue creation. Exceptions require architecture review board approval and quarterly renewal.
</enforcement>
