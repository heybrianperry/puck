These rules are ALWAYS ACTIVE for all Remix route modules and service boundary definitions to ensure environment-specific configuration is properly isolated and managed at the route level.
</rule_activation>

### Rules

- **R-REMIX-001** MUST: Environment-specific configuration MUST be isolated within route boundaries and not leak across route modules

### Verify

```bash
# Verify all routes with service dependencies define configuration in loaders/actions
grep -r 'export.*loader' app/routes/ | xargs -I {} sh -c 'grep -L "config" {} || echo "Missing config in: {}"'

# Find direct process.env access outside of loaders/actions (should be empty)
find app/routes -name '*.tsx' -exec grep -l 'process\.env\.' {} \; | grep -v 'loader\|action'

# Verify TypeScript strict mode and linting pass
npm run type-check && npm run lint -- --rule 'no-process-env: error' app/routes/
```

**Accept when:**
- All route modules with service dependencies define configuration objects within loader or action functions
- No direct process.env access exists in route component code (only in loaders/actions)
- TypeScript compilation succeeds with strict mode enabled for all route modules
- Code review checklist confirms service boundaries are explicitly defined for new routes
- ESLint rules preventing direct environment variable access in components pass
- Automated tests verify configuration isolation between routes

<enforcement>
Claude Code MUST NOT skip or defer verification of these rules. All Remix route modules must comply with R-REMIX-001 before acceptance. CI pipeline enforcement via ESLint, TypeScript strict mode, and code review checklists is mandatory.
</enforcement>
