<rule_activation id="1099d4d1-bde1-42cc-affd-2aaa518a96a2" title="Standardize Runtime Configuration Loading with Concurrent Environment Resolution: Configuration Loading Logic" applies_to="**/*">
These rules are ALWAYS ACTIVE for all runtime configuration and environment management implementations across the codebase, including API route handlers, server-side modules, client-side components, and configuration initialization code in Next.js, React Router, and similar frameworks.
</rule_activation>

### Rules

- **R-CONFIG-001** MUST NOT: Configuration loading logic MUST NOT introduce blocking operations that could create deadlocks or performance bottlenecks under concurrent access.

### Verify

```bash
# Count environment variable access patterns
grep -r 'process\.env' --include='*.ts' --include='*.tsx' | grep -v 'node_modules' | wc -l

# Find configuration loading and environment resolution patterns
find . -name '*.ts' -o -name '*.tsx' | xargs grep -l 'config.*load\|environment.*resolve' | grep -v node_modules

# Run configuration and environment tests with coverage
npm test -- --testPathPattern='config|environment' --coverage
```

**Accept when:**
- All configuration loading code follows the standardized pattern with documented concurrent access semantics
- Integration tests demonstrate thread-safe behavior under concurrent access from multiple execution contexts
- Code review checklist includes verification of configuration pattern compliance for new API routes and server modules
- Performance benchmarks show no significant regression in configuration loading latency compared to baseline
- No blocking operations detected in configuration loading paths
- Memoization or caching is implemented for resolved configuration values

<enforcement>
Claude Code MUST verify configuration loading patterns comply with R-CONFIG-001 before approving changes to runtime configuration, environment variable resolution, or configuration initialization code. Violations MUST be flagged and remediated before merge.
</enforcement>
